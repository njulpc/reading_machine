# Lightweight Vision Transformer Compression for On-Device Plant Disease Detection in Resource-Constrained Agricultural Field Conditions

官方证据：[摘要及提交历史](https://arxiv.org/abs/2609.05334)、[v1 全文](https://arxiv.org/html/2609.05334v1)。v1：2026-09-04 16:40:06 UTC，即北京时间 **2026-09-05 00:40:06**。主分类cs.CV，交叉cs.AI/cs.LG。本次读取§1–5的方法、表格和结论；论文实验与本地Qwen迁移结果分开陈述。

## 1. 核心速览

**研究主题：** 曲率引导的结构剪枝、注意力蒸馏与动态INT8后训练量化的组合，主归类quantization，兼有pruning/knowledge_distillation。

**一句话总结：** ViT-B/16到TinyViT再做INT8使文件从327.42MB降为6.01MB（54.5倍），但同尺寸学生直接训练也达到接近的精度，论文尚未证明三阶段方案普遍优于简单基线。

## 2. 研究背景与动机

农业病害识别中的背景、相机和村庄差异会掩盖模型真实泛化，而大ViT的存储与算力不适合低端设备。压缩技术的组合也未必可叠加：剪枝会改变教师知识，蒸馏会改变学生分布，最终量化的损失不能由每项单独实验相加预测。

作者采用按村庄/相机隔离的数据评估，并显式比较单独组件、串行流水线及同尺寸直接训练学生。这比单报高压缩比更能回答是否值得承担额外训练成本。

## 3. 核心方法与创新点

1. **H-BAC块预算。** 对注意力和MLP参数分别用K=10个Rademacher向量计算Hutchinson Hessian trace，以`C_b=Hattn+λHmlp`得到块曲率。算法1对累计曲率取max(C,0)，用`sqrt(C)/mean(sqrt(C))`直接分配全局剪枝率，再做[0.05,0.95]裁剪、均值重标定和第二次裁剪。它给高曲率块更多剪枝，并非逆曲率保护；第二次裁剪后也不保证预算均值严格相等（§3.3）。
2. **块内结构掩码。** 按一阶Taylor重要度删除注意力头对应QKV切片及输出列，删除MLP对应输入行/输出列；训练保持梯度掩码，进行一轮恢复。掩码不改变原张量形状；真实部署缩形应单独完成。正文对负曲率“绝对值”与算法max(C,0)、MLP的Taylor与L2排序叙述存在不一致，本次实现遵循算法1并明确选择（式1–5、算法1）。
3. **注意力蒸馏。** ViT-B/16为85.80M参数，TinyViT为5.52M；将第3/6/9/11层的注意力在头维平均后做MSE，绕过768/192特征维度和12/3头数量差异。目标为`0.5Lhard+0.3Lattention+0.2Lsoft`，温度T=4、soft项含T²缩放。流水线先剪教师，再蒸馏15轮（§3.5–3.6）。
4. **最终量化是PTQ。** 最终已训练学生的全部Linear采用动态QINT8，无额外训练、无需离线激活校准；对照静态PTQ使用1,000张训练图像、按类加权随机采样。尽管引言提QAT，最终方法与表6明示PTQ，不能写成执行了QAT。论文未给出完整observer、粒度及后端配置；其Core ML延迟使用的是权重INT8解量化回浮点路径，与PyTorch动态量化内部激活处理不同。

## 4. 实验设计与结果

三类辣椒叶片：健康、ChiLCV早期、重症；训练17,655、验证2,207、普通测试2,207、OOD760张，村庄互不重叠，OOD另来自3种未用于其他切分的手机。224×224输入、ImageNet归一化；基线AdamW lr1e−4、weight decay1e−4、label smoothing0.1、3轮warmup、余弦衰减和早停。CPU为M4 Pro/Core ML，GPU为RTX4060/PyTorch；batch128计时后除以128，不能当单请求手机延迟（§3.1–3.2）。

| 设置 | 文件体积 | OOD精度 | 关键对照 |
|---|---:|---:|---|
| ViT-B/16 FP32 | 327.42MB | 95.13% | 85.80M参数、35.13G FLOPs |
| H-BAC 50%，恢复后 | 327.42MB掩码文件 | 95.53% | 活跃43.70M，17.86G FLOPs |
| 仅动态PTQ | 84.42MB | 94.34% | 精度−0.79点；CPU7.21ms vs FP32 7.18ms |
| 仅静态PTQ | 85.78MB | 94.61% | 精度−0.52点；精度来自不同PyTorch路径 |
| TinyViT无KD | 21.15MB | 96.58±0.26% | 表7，3次运行 |
| 注意力KD | 21.15MB | 96.71±1.03% | 较无KD均值仅+0.13点 |
| 全流水线最终INT8 | 6.01MB | 单次91.97%；4配置95.13±2.32% | 3个50%及1个70%剪枝配置，不是固定配置4种子 |
| 同尺寸直接训练+INT8 | 6.01MB | 94.87% | 无剪枝、无蒸馏 |

表5的50%剪枝在恢复前H-BAC为64.87%，均匀分配41.32%，直接曲率分配较好；恢复后95.53% vs93.16%。但此优势属于大骨干中间模型，不直接证明最终6.01MB端点更好。表8更小学生的KD效果大幅波动，部分设置反而退化。

**证据冲突必须保留：** §3.6段落写剪枝恢复94.34%，表4写95.53%；§4.6一处写直接训练95.13%、流水线均值95.39%，与表4/13和结论中的94.87%/95.13%不同。本文采用主要表格与结论交叉一致的值，并不默默修正原文。表4脚注还写延迟“pending re-measurement”，与其他段落的已测措辞冲突；延迟证据可信度因此下调。§4.4声称精度随剪枝率单调，表5恢复后数据并不支持，二分搜索的精度最优性也不能由此保证。

**本地真实迁移验证：** [复现说明](../../../../scripts/quantization/2609.05334/README.md)与[代码](../../../../scripts/quantization/2609.05334/demo.py)使用本地完整Qwen3-0.6B checkpoint；完成全模型197个Linear的native动态INT8，以及选择块的CE Hessian、Taylor掩码、恢复、注意力蒸馏和学生INT8。原始输出JSON与命令见复现目录。本次未复现视觉数据精度、54.5倍文件缩减或Core ML计时，完整论文复现状态为false。

## 5. 局限性与未来展望

- 最终体积主要由学生架构和INT8决定，掩码剪枝本身不缩文件；不能把活跃参数减半当磁盘体积减半。
- 注意力KD较同尺寸直接训练的均值优势小于方差，4种配置混合统计不能证明固定方法稳定无损。
- Core ML权重INT8基本没有延迟收益，且没有低端Android手机测量、CUDA原生INT8成品；54.5倍体积绝不等于54.5倍加速。
- 文本/表格矛盾、未明确λ和observer等配置、未找到论文自有代码链接，均妨碍严格复现。
- 后续应提供相同数据、预算、种子数的直接训练控制，固定配置误差条，H-BAC负曲率和预算实现，以及目标硬件上的真实量化执行图。

## 6. 学术启发

组合压缩研究应把“模块是否有效”与“最后端点是否更优”分开：剪枝对中间大模型有益，仍可能使教师变弱。一个合理实验矩阵应包含大教师→小学生、剪枝教师→小学生、小学生直接训练三条路径，并在相同位宽、体积和训练预算下比较。

**评分（1–10）：** 精度效果6（有OOD控制，但端点收益不确定且文本冲突）；压缩8（6.01MB与54.5倍文件数据明确）；创新6（曲率预算与既有组件组合，缺少普遍优势）；可复现性5（本地真实组件运行成功，论文精确配置和视觉复现仍不足）。
