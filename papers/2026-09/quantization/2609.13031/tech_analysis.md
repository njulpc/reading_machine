## 1. 核心速览

研究主题：表格基础模型 ICL 阶段的 E4M3FN FP8 注意力量化。

一句话总结：同步量化 train–train 与 test–train 注意力，并复用训练查询尺度，可在大表上获得至多 1.67× 端到端加速；只量化一侧会明显损害质量。

## 2. 研究背景与动机

TabPFN/TabICL 权重规模相对较小，但训练样本行数 N 可以很大。ICL 的 train–train 与 test–train 注意力代价为 O(N²+MN)，权重投影仅 O(N+M)，因此注意力矩阵乘比压缩权重更值得优化。训练行同时构成键值，测试行只是查询；这两个调用的误差协调问题不同于普通因果 LLM。

## 3. 核心方法与创新点

1. **动态逐头尺度**：对每个头的 Q/K/V，跨行与通道取 absmax，s=max|X|/448，以 FP32 存尺度，将 X/s 裁剪到 [−448,448] 并转 E4M3FN。无需静态校准集或梯度更新；零张量的尺度保护是本次实现补充。
2. **P 的固定指数平移**：融合在线 softmax 中把未归一化指数的行最大值提高到 2⁸=256，再转换 FP8，用足指数范围，避免小概率过早下溢。分母累积原浮点指数，PV 使用 FP8 指数值，Q/K 尺度并入 logits，V 尺度在输出端恢复。
3. **两侧协调**：train–train 与 test–train 共用同一版本的量化 K/V。测试 Q 复用训练 Q 的逐头尺度，避免测试批大小改变预测；测试 Q 超过训练范围时会被裁剪，这一点不能忽略。
4. **按长度启用**：最终方案仅 N>8192 启用 FP8；小表的量化开销不划算。RTX PRO 6000 Blackwell 上用 Triton 实现类似 FA2 的融合循环。论文不是权重量化，也没有证明完整模型文件缩小两倍。

## 4. 实验设计与结果

TabPFN-v3 在 TabArena 51 数据集、3 个预处理种子上评估。表 1 无长度门控时：只量化训练侧误差 +2.81±0.73%、Elo −31.8±4.1；只量化测试侧误差 +2.38±0.77%、Elo −20.3±2.4；两侧量化且共享训练 Q 尺度则为 +0.02±0.03%、Elo −1.3±0.3。这里误差变化为每数据集 metric_error 的相对变化，不是准确率百分点。共享方案的单侧 sign-test p=0.024–0.080，说明“很小”不等于绝对无损。

最终门控覆盖 TabArena 18 个会变化的数据集，三种子 Elo −0.1/−0.5/−0.3，其中一组 p=0.048。BeyondArena 有 142 数据集、56 个超过门限，Elo −2.0/+0.6/−0.1，p=0.344/0.656/0.930。

表 3 在 RTX PRO 6000 Blackwell Server Edition 上比较 torch SDPA/FA2。单核 B=1、8 头、D=64、FP16 输入，计入 QKV 量化成本；端到端 predict 使用 20 特征和 1024 测试行。N=512k 时内核 1579.215→919.782 ms，即 1.72×；端到端 334.499→200.375 s，即 1.67×。N=1k 时 FP8 内核仅 0.30×，支持长度门控。TabICLv2 的 512k 端到端 168.044→107.734 s，为 1.56×。这些是特定硬件与数据形状下的结果。

## 5. 局限性与未来展望

Qwen 因果注意力没有表格 ICL 的训练/测试双调用，故本机只把动态 QKV、FP8 P 与在线累积移植到真实 Qwen，双调用共享尺度另用配对小张量验证。动态全序列 Q 尺度会使量化误差依赖同次 prefill 范围，不能声称逐 token 解码批次不变；本复现仅测 prefill。未实现持久 FP8 KV、权重量化、TabPFN/TabICL 原任务、N>8192 的 GPU 基准及 Triton 融合内核。三段短文本 CE 不是基准困惑度，也不能证明量化提升质量。

论文也显示未门控时有可检测的轻微退化。实际部署还需测训练/测试分布漂移导致的尺度裁剪，以及硬件、头维度、服务批次变化。后续应取得 NVIDIA 硬件并复现 TabArena/BeyondArena，区分量化、内核和总流水线成本。

## 6. 学术启发

相互依赖的两个模块可能需要接受一致误差；逐模块“尽量少量化”并非全系统最优。迁移方法时应寻找共享状态与尺度的不变量，用只量化 A、只量化 B、两者独立、两者协调四组实验验证。精度与速度必须分开做消融，长度门控是部署策略的一部分，不能只报告最大形状的峰值加速。
