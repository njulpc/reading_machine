## 1. 核心速览

一句话总结：ODA 用局部前向后的状态预测是否需要全局 attention，RULER16K 接近原精度；1.98倍加速来自独立受控长上下文配置。

研究主题：按解码步动态稀疏 attention / 条件计算。保留完整历史 KV，压缩的是当步读取和计算量，权重和 KV 容量没有被压缩。

## 2. 研究背景与动机

长上下文每步读取全部历史很贵，但远距离信息并非每步都能改善下一 token 预测。固定局部窗口代价低却可能错过关键内容；先读取局部状态，再预测全局读取的边际收益，是在无需改动预训练骨干的前提下实现自适应计算的思路。

## 3. 核心方法与创新点

1. Local 保留4个起始位置及含当前 token 的2048窗口；Full 访问全部历史。两种候选从同一个步前缓存出发。
2. recall head 输入前一步选中分支隐藏状态、当前 token embedding、当前 Local 最终隐藏状态，预测 Full 相对 Local 在真实下一 token 上的 NLL 收益。目标减去计算罚项lambda后作带符号log变换，使用Huber回归。只训练head。
3. 分数超过阈值0才从相同步前历史重算 Full，仅提交选中分支的当前KV；不会重复追加缓存。vLLM GPU侧条件执行减少同步开销。
4. 1.7B的head有28,325,889参数：三个2048→1024塔、交互融合、两个SwiGLU残差块；新增参数需计入成本。

## 4. 实验设计与结果

官方表1：Qwen3-1.7B 在RULER16K（13任务×100）Full81.94、Local19.23、ODA81.17，全局调用41.6%；LongBench13任务2550例为37.94/23.66/36.82，调用70.6%。英文passage retrieval仍比Full低10.33分。8B、Qwen3.5-2B、Gemma4-12B-it的RULER Full/ODA分别92.59/91.07、94.35/94.08、96.61/95.27，分别独立训练head。

同调用预算的5任务对照：ODA88.96、Random32.79±0.95，证明调用时机重要。独立受控速度实验：A100-SXM4-80GB、batch1、固定1024输出、约128K输入、规定12.5%全局调用；FLOPs为Full的24.26%，75.54→149.52 tokens/s（1.98倍），不计prefill。4K输入反而慢15.8%。这些运行点不能与任务表41.6%或70.6%的质量直接拼成同一个精度-速度结论。

## 5. 局限性与未来展望

无KV容量节省，另加28.3M head；反复Local+Full会在短上下文或高召回率下亏损。质量和速度采用不同实验协议，且完整匿名实现尚待发布、部分训练GPU小时未报告。生成分布并非精确保持。本文未本机训练head或跑vLLM；后续应在同一任务同一实际召回率下联合测质量/延迟/总显存。

## 6. 学术启发

优化对象应是“这一读取是否改善当前预测”，而非仅预测模型是否不确定。训练标签允许负收益，并用随机同预算对照拆开调用频率与时机。评分：精度8（多骨干保持较好）；压缩5（仅动态计算减少，容量不降）；创新8（冻结模型状态读出收益）；可复现5（细节较全但完整实现与成本记录不齐）。
