# MintAct: A Unified Visual Agent for Digital Environments

## 1. 核心速览

**研究主题**：把手机、桌面、网页及视觉工具调用的领域 RL 专家整合到单一视觉语言代理，并进一步做跨域 RL。

**一句话总结**：MintAct 用成功轨迹筛选与监督学习完成四域专家蒸馏，8B模型的 Weblica 从 SFT 的57.5升至 RFT 的72.8，但桌面和网页仍落后各自教师；最终 OSWorld-Verified 48.9 包含后续联合RL贡献，不能全部归因于蒸馏。

## 2. 研究背景与动机

每个数字环境单独维护一个专家会增加模型部署与服务成本；直接混合数据又容易让动作空间、分辨率、环境速度和训练分布相互干扰。本文将单模型多域执行作为目标：同一套权重处理像素定位、长程导航及工具调用，以领域系统提示限定动作集。

“压缩”主要体现在**多套专家能力归入一个权重集合**。教师与学生可以同为8B；论文还训练2B/4B学生，但这不自动构成某一大教师被严格压缩为4倍大小的对照。论文未报告统一系统与专家服务集群的实测存储/显存倍率。

## 3. 核心方法与创新点

1. **两阶段预热**（§3.3）。高分辨率单步SFT负责定位，最大2,116,800像素；低分辨率多步SFT负责交互，最大921,600像素。均训练1 epoch、学习率1e-5。第二阶段四域约42.7k/23.5k/51.7k/59.8k轨迹，重采样到各25%，保留完整截图历史，移动/桌面/网页最多30轮、工具最多100轮。
2. **四域专家生成→质量筛选→单模型RFT**（§3.3.3）。从预热模型训练各域RL专家；移动/桌面/网页各生成一轮，工具域生成四轮；强VLM评判器保留成功轨迹。最终约37.8k、21k、7k、24k条，合计约89.8k。随后从同一SFT模型出发，以标准自回归负对数似然拟合教师的思考及动作序列。这里是离线轨迹蒸馏，正文未采用全词表教师logits KL，也不能把评判器当成被压缩的唯一教师。
3. **明确的蒸馏训练设置**。RFT学习率3e-6、1 epoch、AdamW、weight decay 0、global batch64、cosine schedule及0.1 warmup、最大序列60,000，四域25:25:25:25混合；视觉编码器和多模态投影器冻结，语言部分微调。模板化损失可写为在筛选数据上最小化 `-sum log p_theta(reasoning, action | domain prompt, screenshot history)`；论文没有报告额外量化、稀疏或低秩操作。
4. **动态工具注册的训练对齐**。工具集合改变时分段，保留完整历史但仅对新引入动作计算损失，使每个助理动作监督一次。它修正训练条件，而非压缩KV缓存；所有旧截图仍留在上下文。
5. **蒸馏后的联合异步RL**。按领域配额接收样本并对快域施加背压，控制数据混合；用dual-clip surrogate处理策略滞后，用截断重要性权重处理训练/推理数值差异。附录表B：4个trainer节点、12个rollouter节点、每5步同步、队列448、group8、mini-batch48、250步、lr4e-6、KL系数0、TIS阈值2。实际联合RL仅移动25%和桌面75%，不是四域共同RL。

## 4. 实验设计与结果

底座为Qwen3-VL-Instruct，学生2B/4B/8B。评测涵盖四项定位、AndroidControl/AndroidWorld、OSWorld-Verified、Weblica/Online-Mind2Web和MM-ToolSandBox；导航最多30步、工具最多100步。以下摘取**表6的8B阶段消融**，数值沿用各基准原指标：

| 模型 | AndroidWorld | OSWorld-Verified | Weblica | Om2W | MM-ToolSandBox |
|---|---:|---:|---:|---:|---:|
| 各域RL专家 | 67.8 | 49.2 | 77.1 | 39.8 | 22.5 |
| MintAct-SFT-8B | 63.8 | 42.6 | 57.5 | 30.0 | 19.8 |
| MintAct-RFT-8B | 68.1 | 43.1 | 72.8 | 36.3 | 21.3 |
| MintAct-8B-Final | 67.0 | 48.9 | 74.7 | 39.1 | 24.5 |

RFT相对SFT分别+4.3/+0.5/+15.3/+6.3/+1.5点。相对各自专家，RFT在AndroidWorld高0.3点，但桌面低6.1、Weblica低4.3、Om2W低3.5、工具低1.2点，因此“保留各域能力”不等于所有指标无损。

后续联合RL使桌面43.1→48.9（+5.8），同时AndroidWorld68.1→67.0（-1.1）。定位也并非全面提升：8B的MMBench-GUI在SFT/RFT/Final为82.7/81.7/80.8。最终模型多项强表现不能用作蒸馏单独效果。

跨规模：2B的AndroidWorld SFT→RFT为44.8→55.7，Weblica44.4→55.6；4B分别53.5→62.4、57.1→65.8。正文提供了小模型同规模阶段收益，未充分给出不同规模全部教师来源及逐教师到学生的成本匹配比较。

**压缩倍率边界**：如果四个独立8B专家都常驻、没有共享权重，换为一个8B模型可将“模型权重集合数量”从4降至1，名义权重容量约4倍；这是条件算术，不是本文测出的端到端显存/服务成本倍率。按请求只加载一个专家、共享底座、缓存、训练成本等均会改变实际收益，不能将这个假设倍率作为已验证结果。

## 5. 局限性与未来展望

- RFT丢弃失败轨迹，VLM评判器的误判和成功样本选择偏差可能限制困难任务学习；需要审计过滤精度、各域成功率与失败恢复能力。
- 单模型仍存在领域性能回落。正文缺少多种子置信区间及部署延迟、峰值显存、能耗与总成本对照，无法量化质量差是否显著或部署收益有多大。
- 训练基础设施很重。4+12节点及大量交互环境并不意味着压缩过程本身便宜；表B给的是节点数，不能擅自换算GPU张数。
- 作者明确把四域共同RL、长期上下文管理、按需在UI动作和工具之间切换、端侧/云端协作列为未来方向。本文未实现旧截图剪枝或KV缓存压缩。
- 动态工具引起上下文重建，RL对分段使用轨迹级奖励、主要训练最后一段，信用分配仍粗糙。

## 6. 学术启发

可迁移方案是“**先让专家专门化，再通过筛选后的行动序列整合能力**”。对于压缩研究，应该固定学生初始化与参数量，以SFT→RFT衡量蒸馏净收益，再单独测后续RL；同时用教师集合中每个领域的性能画出保真曲线，避免平均值掩盖桌面退化。

另一个实验设计要点是给多教师蒸馏制定真实服务成本基线：比较四专家常驻、按需加载、共享底座和单模型四种部署条件，并把数据收集、评判器和RFT训练成本计入。这样才可把“只保留一套权重”转化为可验证的压缩收益。

**评分（1–10）**：精度效果8（跨2B/4B/8B有阶段消融，仍有域间退化）；压缩倍率5（清楚减少专家权重集合，实测存储/显存倍率缺失）；创新性7（多域轨迹蒸馏结合统一代理及异步训练控制，核心RFT目标本身常规）；可复现性5（轨迹数量、混合比与超参较完整，但需教师、评判器、环境和大型交互训练资源）。
