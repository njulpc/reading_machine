# Muir: Linear Attention with Sensitivity-Allocated Gating and Matched-Filter Readout

## 1. 核心速览

**研究主题**：other / Muir。

**一句话总结**：Muir按状态更新敏感度分配低秩门控，用匹配滤波读出改善固定容量记忆；节省参数用于加宽FFN，因此不宣称整模型参数缩小。

## 2. 研究背景与动机

线性attention把历史压入固定矩阵状态，避免随上下文增长的KV缓存；但不同门控和状态行承担的作用不均。GDN-2给擦除与写入较大投影预算，而归一化key使擦除只作用于少数活跃方向；慢衰减状态行又可能支配读出并迫使系统过度擦除。

## 3. 核心方法与创新点

1. 分析Gated Delta规则 `S=(I-kᵀ(b⊙k))Diag(α)Sprev+kᵀ(w⊙v)`；擦除沿key方向，写入覆盖value通道，故对写门扰动更敏感。
2. 融合门控并分配不对称低秩。d=2048时Muir采用衰减/擦除/输出/写入/动态读出rank为64/64/128/128/128，FFN宽7680；GDN-2对应FFN宽5888。
3. 匹配滤波读出结合静态通道profile与动态token调制，校正不同状态行的能量，降低无谓擦除。
4. boundary-pivoted chunk kernel把相对衰减分段，避免长chunk前缀下溢及除法溢出，再用块矩阵运算求解三角系统。

## 4. 实验设计与结果

在166M、406M、834M、1.34B四尺度训练100B token，评测FineWeb-Edu、WikiText、LAMBADA、8项常识及检索。表1的1.34B：WikiText PPL Transformer17.17、GDN-2 16.80、Muir16.41；8任务平均52.05%、52.46%、53.84%，并非所有单任务均最优。表2给出rank/FFN受控对照。

机制测量中写/擦除敏感度比约13.3；状态row能量p90/p10从17.2经读出调整至9.6。论文称1.34B模型以25MB FP32状态外推到10M-token流，而Transformer若存BF16全KV需2.1TB；这是特定模型长度下的状态容量对比，不代表无损保留任意历史。近100% passkey到1M的结果对应static readout变体。Muir匹配GDN-2吞吐，达到后者100B-token验证损失约快1.2倍；32K训练相对Transformer约快2.7倍。

本次核验方法、rank和实验表，未运行训练或kernel。

## 5. 局限性与未来展望

研究从头训练架构，不是把现有Qwen checkpoint直接压缩；低秩门控省下的参数重新投入FFN。有限状态对一般检索仍有容量限制，25MB不能解读为无损压缩2.1TB。不同readout变体在不同任务各有优势；TPU大矩阵单元收益不自动等于消费GPU或CPU收益。

## 6. 学术启发

局部压缩应该按扰动对输出的敏感度分配rank，而不是平均切分所有矩阵。重分配参数预算时须固定总参数和训练token；把长上下文容量、检索准确率和真实kernel吞吐一起测，才能证明架构收益。

**四维评分（1–10，编辑判断而非客观排名）**：精度效果 8/10；压缩倍率 7/10；创新性 8/10；可复现性 6/10。

精度8：多尺度100B-token训练与检索对照；压缩7：状态随序列长度保持常数，但总参数匹配；创新8：门控敏感度、读出与稳定kernel联动；复现6：理论和rank可核验，本次未进行TPU训练。
