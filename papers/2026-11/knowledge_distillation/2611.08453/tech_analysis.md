# Unpacking the Compute Efficiency of Strong-to-Weak OPD against GRPO

> arXiv: 2611.08453；v1：2026-11-05T18:47:05+00:00（UTC） / 2026-11-06T02:47:05+08:00（北京时间）。
> 分类：Machine Learning (cs.LG) ; Computation and Language (cs.CL)。归档以 v1 北京时间月份为准。
> 证据：[官方摘要与提交历史](https://arxiv.org/abs/2611.08453)；[官方HTML全文](https://arxiv.org/html/2611.08453v1)。以下论文结果均为作者报告，本地结果另行标注。

## 1. 核心速览

**研究主题**：knowledge_distillation / OPD成本审计。

**一句话总结**：外部强教师不必然提高每FLOP学习效率；同源专家蒸馏的价值在于多域能力合并，而非孤立计算50倍蒸馏阶段节省。

## 2. 研究背景与动机

强教师的逐token监督比终局奖励密集，却要对每个学生生成token额外执行一次教师前向。只比较梯度步数、样本量或蒸馏阶段GPU小时，会掩盖教师成本以及回答变长带来的计算膨胀。本文直接比较达到相同held-out准确率所花的累计训练FLOPs。

## 3. 核心方法与创新点

1. 学生自己采样rollout，在每个位置取学生概率最高的16个token，分别重归一化教师与学生在该集合上的概率，计算闭式反向KL；不把结果奖励混入该OPD损失。
2. 受控比较固定学生初始化、提示、rollout group及公共超参数，改变任务难度、教师大小与训练来源。默认8条rollout，并单独分析1条设置。
3. 计算账本把GRPO近似记为每生成token `10Ns`：生成2Ns、重算logprob 2Ns、更新6Ns；OPD增加教师前向2Nt。共享prompt上下文不计入，故这是明确边界的FLOP估计，不是硬件实测。
4. 每个领域先训练学生自身的GRPO checkpoint，再按领域路由教师做多教师OPD，将不同专家能力合并到一个学生。

## 4. 实验设计与结果

主要学生是Qwen3-1.7B/4B/8B，外部教师最高32B；数学使用DAPO-Math-17K、DeepMath-103k，代码使用LiveCodeBench v1–v5及CodeForces子集。数学OOD指标对AIME24、AIME25、AMC23取宏平均，评测mean@16；代码测试LiveCodeBench v6的175题。

外部post-trained教师在大部分匹配设置下不如GRPO高效；1 rollout的外部OPD仅在单域数学出现例外。Qwen3-4B学生用自己的GRPO checkpoint当教师，1 rollout蒸馏阶段可用约1/50 FLOPs恢复目标分数，默认8 rollout时约1/6。这两个比值都未包括生成教师的GRPO训练。两域、四域专家合并额外蒸馏成本分别为专家训练量的5.2%、8.0%；两域全流程计入专家训练后，以比joint GRPO少42.0%的总FLOPs达到同等性能（§3–6、图1）。

## 5. 局限性与未来展望

50倍不是全流程加速，也不是50倍模型压缩。同源教师和学生可以同尺寸，单域时教师本身就是可部署模型，再蒸馏只会增加成本。截断到top-16、FLOP近似忽略prompt、有限域和训练预算都会影响外推；不能据此否定所有蒸馏目标。未来应把教师训练、数据生成、长输出和硬件通信成本放入同一账本。

## 6. 学术启发

比较蒸馏方案时同时画“准确率—完整成本”和“准确率—部署资源”曲线，避免把训练效率与推理压缩混成一个数字。教师选择不仅看考试分数，还要测与学生的分布距离和训练谱系；多专家合并需要与同预算joint训练比较。

**四维评分（1–10，编辑判断而非客观排名）**：精度效果 7/10；压缩倍率 3/10；创新性 8/10；可复现性 6/10。

精度7：跨尺寸/领域有受控对照，但外部教师常输GRPO；压缩3：同源专家合并不提供单模型字节压缩率；创新8：拆分教师来源与完整训练账本；复现6：目标和FLOP公式清晰，但本次未跑多GPU训练。
