# 深度技术分析：Stage-Replay Divergence Follows the KV Cache: Fixed-Prefix Precision Controls and Bidirectional Cache Transplantation

## 1. 核心速览

**研究话题**：Stage-replay 诊断中中间 token 前缀重构造的假设审计——KV Cache 是轨迹分歧的因果充分载体。

**一句话总结**：在 Qwen2.5 衍生系统上通过 200 项匹配实验发现，BF16 精度下相同整数 token 的保留实时 cache 与一次性 prefill 构造在 166 个后缀和 20 个正确性标签上产生差异，但准确率差异仅 1 个百分点（95% CI [-3.5, +5.5]）；而 FP32 下无解码分歧；双向移植全部 48 层 K/V cache 使所有分歧延续都跟随 cache 供体——证明在测试状态下，边界 K/V cache 是分歧轨迹的因果充分载体，数值精度调节其行为表达。

## 2. 研究背景与动机

### 2.1 Stage-Replay 诊断的基本假设
Stage-replay 诊断通过重构造中间 token 前缀并将新鲜 prefill 延续视为"从原始达到该前缀的解码状态继续"，来审计 LLM 推理系统的中间状态。但这一假设是否成立——即相同 token 序列的保留实时 cache 与重新 prefill 是否等价——尚未被严格验证。

### 2.2 精度与状态保真度的关联
在 BF16 等低精度格式下，数值误差可能在长链推理中累积，导致保留状态与重构状态之间的差异。理解这种差异的因果结构对诊断工具的可靠性至关重要。

## 3. 核心方法与创新点

### 3.1 方法概述
本文设计了一套严格的审计实验：
1. **200 项匹配实验**：在 Qwen2.5 衍生系统上，比较保留的实时 cache 与一次性 prefill 相同整数 token 的精确副本
2. **固定前缀 $2\times2$ 设计**：保持 200 个 token 状态不变，交叉构造方式和精度（BF16 vs FP32）
3. **增量式保真度桥接**：token-by-token 增量 cache 与保留实时 cache 在 12/12 行上达到比特精确
4. **双向 Cache 移植**：将全部 48 层 key/value 从一种构造移植到另一种，观察分歧延续是否跟随 cache 供体

### 3.2 分点创新
- **精确副本对照设计**：在两侧放置完全相同的整数 token 副本，消除 token 差异的混淆
- **固定前缀 $2\times2$ 因子实验**：系统分离"构造方式"和"数值精度"两个变量
- **比特精确桥接验证**：通过增量式验证确保 saved-ledger 审计可复现每一条保留轨迹
- **双向移植因果推断**：如果移植 cache 后分歧方向跟随供体，则证明 cache 是分歧的因果充分条件
- **跨检查点复制**：在主检查点（24/24）和后期盲复制检查点（43/43）上均验证成功

## 4. 实验设计与结果

### 4.1 实验设置
- 系统：Qwen2.5 衍生系统
- 实验规模：200 项匹配实验
- 精度条件：BF16、FP32
- Cache 层数：48 层 key/value
- 验证级别：比特精确（bit-exact）

### 4.2 核心实验结果
- **BF16 分歧**：保留实时 cache 与 prefill 构造在 **166 个后缀** 和 **20 个正确性标签** 上产生差异
- **准确率差异微小**：BF16 下准确率差异仅 **1 个百分点**，95% 配对 CI 为 [-3.5, +5.5]
- **FP32 无分歧**：FP32 精度下**无解码分歧**，95% Wilson 上界 1.88%
- **增量桥接**：token-by-token 增量 cache 与保留实时 cache 在 **12/12 行** 上比特精确
- **Saved-ledger 审计**：复现每一条保留轨迹和比较指纹
- **双向移植**：
  - 主检查点：选定集合上 **24/24** 的移植使分歧跟随供体
  - 后期盲复制检查点：**43/43** 的移植使分歧跟随供体

### 4.3 结果讨论
实验结果揭示了一个深刻结论：在测试状态下，**边界 K/V cache 是分歧轨迹的因果充分载体**，而数值精度（BF16 vs FP32）调节这一因果关系的"行为表达"。BF16 下的微小差异（166/200 后缀）在准确率层面几乎不可检测（1 个百分点），但在诊断层面却意味着 stage-replay 假设的严格不成立。FP32 下的零分歧则表明，如果追求严格的可复现性，高精度格式是必要的。

双向移植实验（100% 成功率）是因果推断的强证据：当 cache 被移植后，分歧方向完全跟随 cache 的"供体"，这符合"cache 是因果充分条件"的预测。

## 5. 局限性与未来展望

### 5.1 局限性
- 仅在 Qwen2.5 衍生系统上验证，其他架构（如 LLaMA、GPT）上的行为可能不同
- 200 项实验的样本量对统计推断而言相对有限
- 仅测试了 reasoning-stage 边界，其他类型的 stage 边界（如工具调用边界、多轮对话边界）未涉及
- 未探索 INT8/INT4 等更低精度格式下的行为
- 未讨论在实际推理系统中维持 FP32 cache 的显存代价

### 5.2 未来展望
- 跨架构验证：在 LLaMA、Mistral、GPT 等不同架构上重复实验
- 更大规模审计：扩展实验规模以提高统计功效
- 精度-保真度权衡：建立 BF16 vs FP32 在不同应用场景下的选择指南
- 低精度 cache 的补偿策略：如果必须使用 BF16，设计数值补偿机制以恢复 FP32 级别的可复现性
- 将发现应用于 KV cache 压缩/量化方法的可靠性评估

## 6. 学术启发

### 6.1 可迁移思路
- **精确副本 + 双向移植的因果推断范式**：这是验证"某状态是否为某行为因果载体"的通用强方法——先在精确控制下观察差异，再通过状态移植验证因果方向
- **精度作为行为表达调节器**：数值精度不仅影响准确率，还影响系统的因果结构——这对任何涉及数值近似的系统（量化、稀疏、蒸馏）都有启示

### 6.2 实验设计借鉴
- 固定前缀 $2\times2$ 设计是控制复杂系统中多个混淆变量的典范
- 配对置信区间和 Wilson 区间的联合使用提供了稳健的统计推断
- 跨检查点的盲复制（outcome-blind replication）增强了结论的可信度

## 7. 总结

本文通过严格的对照实验，揭示了 stage-replay 诊断中一个关键但易被忽视的假设漏洞：BF16 精度下相同 token 的保留 cache 与重新 prefill 并不完全等价。实验进一步证明边界 K/V cache 是分歧轨迹的因果充分载体，而数值精度调节其行为表达。这一发现对 LLM 推理系统的可复现性诊断、KV cache 管理策略以及精度选择决策都具有重要影响。
