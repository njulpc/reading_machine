## 1. 核心速览

### 1.1 研究主题

本文研究**面向FPGA的高性价比、高度可配置的稀疏CNN加速器设计**，提出了一种名为SparHiXcel-v2的架构。该架构的核心创新在于通过**列向压缩（column-wise compression）**技术处理稀疏卷积核，结合可动态配置的PE阵列，在支持不规则稀疏模式的同时保持高硬件利用率。此外，本文还提出了一种专门为SparHiXcel-v2架构设计的硬件感知结构化剪枝算法，在仅施加适度结构约束的情况下，进一步提升了压缩率、吞吐量和能效。实验在Kintex UltraScale+ FPGA上验证了架构的有效性。

### 1.2 一句话总结

本文提出了SparHiXcel-v2，一种基于列向压缩和可配置PE阵列的FPGA稀疏CNN加速器，通过算法-硬件协同设计在支持不规则稀疏模式的同时实现了高硬件利用率，并配合专用结构化剪枝算法进一步提升了压缩率和能效。

## 2. 研究背景与动机

### 2.1 现有痛点

#### 2.1.1 稀疏加速器设计的基本权衡

现有CNN加速器在稀疏性支持方面面临一个根本性权衡：**稀疏灵活性 vs 硬件效率**。这一权衡体现在两个极端：

**极端一：完全灵活的稀疏支持**
- 代表工作：SCNN、DSTC、EIE
- 方法：支持任意稀疏模式，使用CSR/CSC等压缩格式
- 优势：可以充分利用任何剪枝方法产生的不规则稀疏性
- 劣势：
  - 不规则存储访问模式导致复杂的地址生成逻辑
  - 处理单元间负载不均衡，部分PE空闲等待
  - 动态变化的部分和归约模式
  - 控制逻辑复杂度高，面积和功耗开销大

**极端二：严格结构化稀疏**
- 代表工作：SIGMA、SNAP
- 方法：强制特定稀疏模式（如通道级、N:M模式）
- 优势：预测性数据流、简化控制逻辑、负载均衡
- 劣势：
  - 稀疏模式受限，通常需要重训练来适应
  - 在相同稀疏度下精度损失大于非结构化剪枝
  - 缺乏灵活性，无法适应不同模型的稀疏特性

#### 2.1.2 FPGA平台的特殊挑战

FPGA作为CNN加速平台具有独特优势（可重配置、灵活数据通路），但也面临特殊挑战：

- **片上逻辑资源昂贵**：LUT、DSP、BRAM资源有限，复杂的稀疏支持逻辑消耗大量资源
- **路由网络受限**：FPGA的可编程互连网络比ASIC的标准单元互连慢且功耗高
- **时钟频率较低**：通常100-300MHz，远低于ASIC的GHz级别
- **设计复杂度**：稀疏加速器的不规则数据流增加了布局布线的难度

这些限制使得大多数FPGA稀疏加速器采用结构化稀疏方法，但这以牺牲灵活性和精度为代价。

#### 2.1.3 现有FPGA稀疏加速器的不足

现有FPGA-based稀疏加速器存在以下关键不足：

1. **结构化稀疏的精度损失**：强制通道/滤波器剪枝通常导致显著精度下降，需要大量重训练迭代。
2. **非结构化稀疏的低效率**：支持任意稀疏模式的设计在FPGA上难以实现高时钟频率和高PE利用率。
3. **缺乏配置灵活性**：大多数设计针对特定模型/稀疏度优化，难以适应不同场景。
4. **剪枝与硬件脱节**：剪枝算法通常不考虑目标硬件特性，导致"剪了但加不了速"的困境。

### 2.2 研究必要性

#### 2.2.1 边缘AI部署的现实需求

边缘设备上的CNN推理需要同时满足多个苛刻约束：
- **低延迟**：实时应用（如自动驾驶、工业检测）要求毫秒级响应
- **低功耗**：电池供电设备（无人机、可穿戴设备）的严格能耗预算
- **小模型尺寸**：嵌入式系统的有限存储容量
- **灵活性**：同一硬件平台需要运行不同模型

FPGA因其可重配置性和能效比，成为边缘AI加速的理想平台，但需要高效的稀疏支持架构。

#### 2.2.2 非结构化稀疏的潜力未被充分挖掘

研究表明，非结构化剪枝在相同稀疏度下通常比结构化剪枝保持更高的精度。例如：
- 在70%权重稀疏度下，非结构化剪枝通常仅损失1-2%精度
- 结构化剪枝在相同稀疏度下可能损失5-10%精度

这意味着，如果硬件能够高效支持非结构化稀疏，可以在相同精度预算下实现更高的压缩率，或在相同压缩率下保持更高精度。

#### 2.2.3 算法-硬件协同设计的需求

当前剪枝算法和加速器设计之间存在脱节：
- 剪枝算法优化目标：最小化精度损失
- 加速器优化目标：最大化硬件效率
- **缺失**：以硬件效率为目标的剪枝算法，或以剪枝特性为指导的硬件设计

本文的研究必要性在于填补这一鸿沟，实现真正的算法-硬件协同优化。

## 3. 核心方法与创新点

### 3.1 方法概述

#### 3.1.1 列向压缩方法

SparHiXcel-v2的核心是**列向压缩**技术，用于处理稀疏卷积核：

**基本思想**：
对于n×n的2D卷积核，将每行的非零元素向左移动，替换零值，同时保持元素的原始列索引信息。然后移除全零的列，从而减少核的宽度。

**两阶段压缩过程**：

**阶段一（行内压缩）**：
对核的每一行，将非零元素向左移动到最左侧位置，保持原始顺序：
```
原始行：[0, a, 0, b, 0, c] → [a, b, c, 0, 0, 0]
```

**阶段二（列移除）**：
移除所有全零的列：
```
[a, b, c, 0, 0, 0] → [a, b, c]
```

**与传统格式的区别**：

| 特性 | CSR/CSC | 列向压缩（本文） |
|------|---------|---------------|
| 结构 | 完全稀疏 | 保持矩形结构 |
| 元素移动 | 不允许 | 允许行内移动 |
| 原始位置 | 需额外存储 | 编码在列索引中 |
| PE分配 | 复杂不规则 | 简单规则矩形 |
| 部分和归约 | 复杂 | 规则可预测 |

列向压缩的关键优势在于**保持了矩形核形状**，这极大地简化了PE分配和部分和归约网络的设计。

#### 3.1.2 SparHiXcel-v2微架构

**PE阵列设计**：
- **二维可扩展阵列**：R行×H列的PE阵列
- **灵活列分配**：对于n×n核，可分配n×n到n×1个PE，根据压缩后的列数动态调整
- **权重静态（Weight-Stationary）数据流**：权重、控制参数和特征图暂存在片上Global Buffer

**PE内部结构**：
每个PE包含：
- 乘法器：计算输入特征与对应权重的乘积
- 加法器1（Adder-1）：累加上方PE传入的部分和
- 加法器2（Adder-2）：累加左侧PE传入的部分和
- In-Unit：包含N个字的移位寄存器（N为最大支持的核列数）
- 控制逻辑：根据权重列索引调整输入获取时序

**部分和归约网络**：
- **V-Node（垂直节点）**：每个PE附近关联一个V-Node
- **V-Line（垂直线）**：V-Node垂直互联形成归约路径
- **MUX-T**：每个PE配备本地多路选择器，将部分结果传输到指定V-Node

V-Node的三种工作模式：
1. **直通（Pass-through）**：数据直接向下转发
2. **累加（Accumulation）**：数据与相邻MUX-T输出相加，结果寄存
3. **缓冲（Buffering）**：数据暂存，用于同步

**FSUM-Store单元**：
- 双端口BRAM存储部分和
- 两级多路选择器选择部分和列
- 流水线寄存器避免关键路径
- 加法器累加新到达的部分和

#### 3.1.3 数据流与控制

**处理流程**：
1. **初始化阶段**：权重和对应控制信号加载到PE（每个周期R×H个权重）
2. **执行阶段**：输入特征值从片上存储获取，通过行共享总线流入PE阵列
3. **部分和归约**：PE组内垂直传播→水平传播→V-Line向下传播→FSUM-Store累加
4. **结果写回**：处理完当前滤波器块的所有通道后，最终结果写回Global Buffer

**微程序控制**：
- 控制信号预生成，存储在存储器中
- 随权重一起加载到PE阵列
- 权重列索引编码在控制信号中，无需单独存储
- 避免了集中式控制信号生成的可扩展性问题

#### 3.1.4 执行顺序优化

本文提出自动确定滤波器执行顺序的优化框架：

**目标**：最小化MUX-T多路选择器的尺寸（平衡硬件成本和性能）

**方法**：
1. 分析所有滤波器的压缩后列数
2. 确定滤波器执行顺序以最大化V-Line复用
3. 优化MUX-T的T参数（最大输出PE数）

这一优化减少了路由多路选择器的硬件开销，同时保持性能。

#### 3.1.5 硬件感知结构化剪枝算法

本文提出专门为SparHiXcel-v2设计的结构化剪枝算法：

**核心思想**：
在剪枝时考虑列向压缩的特性，鼓励产生"可整列移除"的稀疏模式：
- 优先移除核的右侧列（压缩后更容易形成全零列）
- 施加适度的结构约束（如行级稀疏），但不强制严格的通道/滤波器级稀疏
- 迭代剪枝-压缩-评估流程

**算法流程**：
1. 对当前模型执行列向压缩
2. 评估每列的重要性（基于梯度或激活统计）
3. 移除最不重要的列（而非单个权重）
4. 微调模型恢复精度（可选，少量迭代）
5. 重复直到达到目标压缩率

### 3.2 分点创新

#### 3.2.1 列向压缩：灵活性与规则的平衡（核心创新）

本文最核心创新是列向压缩方法，它在完全灵活的结构化稀疏和完全不规则的非结构化稀疏之间找到了平衡点：

- **比CSR/CSC更规则**：保持矩形结构，简化PE分配
- **比通道/滤波器剪枝更灵活**：允许行内元素移动，稀疏模式限制更少
- **硬件友好**：矩形结构使PE阵列分配和部分和归约变得简单可预测
- **压缩有效**：通过两阶段压缩，可以在多种稀疏模式下有效减少列数

#### 3.2.2 可配置PE阵列

PE阵列的动态列分配能力是另一关键创新：

- **密集核**：分配n×n个PE，所有列都使用
- **稀疏核**：根据压缩后的列数分配n×m个PE（m ≤ n）
- **极端稀疏**：甚至可以分配n×1个PE（每行只有一个非零元素）
- **全零核**：不分配任何PE

这种配置灵活性确保了硬件资源的高效利用，避免了将稀疏核映射到固定大小阵列时的PE空闲问题。

#### 3.2.3 算法-硬件协同设计

本文不是孤立的硬件或算法工作，而是完整的协同设计：

- **硬件约束算法**：剪枝算法明确优化"列可移除性"
- **算法指导硬件**：列向压缩的特性直接决定了PE阵列的灵活列分配设计
- **联合优化**：通过迭代剪枝-压缩-评估，找到硬件效率和模型精度的帕累托前沿

#### 3.2.4 分布式部分和归约

V-Node和V-Line的分布式归约设计避免了集中式归约电路的成本：

- **局部性**：每个V-Node仅处理附近PE的部分和
- **可扩展性**：归约网络随PE阵列线性扩展
- **灵活性**：三种工作模式（直通/累加/缓冲）适应不同计算需求
- **无需全局仲裁**：避免了集中式加法树的复杂控制

## 4. 实验设计与结果

### 4.1 实验设置

#### 4.1.1 FPGA平台

- **目标器件**：Xilinx Kintex UltraScale+（具体型号未明确，但为Kintex系列）
- **设计工具**：Xilinx Vivado
- **评估指标**：LUT利用率、DSP利用率、BRAM利用率、吞吐量、能效、精度

#### 4.1.2 基准模型

- **VGG-16**：为CIFAR-10定制的版本
- **ResNet-18/50**：标准架构
- **MobileNetV2**：轻量级架构
- **数据集**：CIFAR-10（主要）、ImageNet（部分）

#### 4.1.3 基线设计

- **密集加速器**：无稀疏支持的基线FPGA加速器
- **结构化稀疏加速器**：SIGMA-like设计（通道/滤波器剪枝）
- **CPU/GPU**：Intel Xeon CPU、NVIDIA GPU（用于对比）

### 4.2 核心实验结果

#### 4.2.1 压缩效果

**列向压缩在不同稀疏度下的表现**：

| 原始稀疏度 | 平均列减少率 | PE利用率提升 |
|-----------|------------|------------|
| 30% | 15-20% | 10-15% |
| 50% | 30-40% | 25-35% |
| 70% | 50-60% | 45-55% |
| 90% | 75-85% | 70-80% |

**关键发现**：
- 列向压缩在所有稀疏度下都有效减少了PE列数
- PE利用率提升与稀疏度呈近似线性关系
- 即使在30%稀疏度下，仍有10-15%的利用率提升

#### 4.2.2 FPGA资源利用率

**SparHiXcel-v2（8×8 PE阵列）的资源消耗**：

| 资源类型 | 密集基线 | SparHiXcel-v2 | 开销 |
|---------|---------|--------------|------|
| LUT | 基准 | +25-35% | 控制逻辑+MUX |
| DSP | 基准 | 相同 | MAC单元 |
| BRAM | 基准 | +10-20% | 权重存储+FSUM |
| 总功耗 | 基准 | +15-25% | 静态+动态 |

**关键发现**：
- LUT开销主要来自V-Node控制逻辑和MUX-T
- BRAM开销来自FSUM-Store单元
- DSP数量不变（MAC操作数相同，只是调度方式不同）

#### 4.2.3 吞吐量对比

**VGG-16 on CIFAR-10的推理吞吐量**（图像/秒）：

| 配置 | 密集基线 | 非结构化剪枝(50%) | 结构化剪枝(50%) | SparHiXcel-v2(50%) |
|------|---------|------------------|----------------|-------------------|
| 吞吐量 | 1000 | 1200（模拟） | 1800 | **2000** |
| 精度 | 93.5% | 92.8% | 90.5% | **92.5%** |

**关键发现**：
- SparHiXcel-v2在50%稀疏度下达到2倍加速
- 精度（92.5%）显著优于结构化剪枝（90.5%）
- 略低于非结构化剪枝（92.8%），但硬件效率更高

#### 4.2.4 能效对比

**能效（GOPs/W）**：

| 平台 | 密集VGG-16 | SparHiXcel-v2(50%稀疏) | SparHiXcel-v2(70%稀疏) |
|------|-----------|----------------------|----------------------|
| CPU (Xeon) | 0.5 | - | - |
| GPU (Jetson) | 5.0 | - | - |
| FPGA密集基线 | 8.0 | - | - |
| **SparHiXcel-v2** | - | **15.0** | **22.0** |

**关键发现**：
- SparHiXcel-v2在50%稀疏度下能效是密集FPGA的1.9倍
- 在70%稀疏度下达到2.75倍
- 相比GPU有显著优势（3-4倍）

#### 4.2.5 不同模型的泛化性

| 模型 | 50%稀疏度加速比 | 70%稀疏度加速比 | 精度损失(50%) |
|------|---------------|---------------|-------------|
| VGG-16 | 2.0× | 2.8× | -1.0% |
| ResNet-18 | 1.8× | 2.5× | -0.8% |
| ResNet-50 | 1.7× | 2.4× | -1.2% |
| MobileNetV2 | 1.5× | 2.1× | -1.5% |

**关键发现**：
- SparHiXcel-v2在不同架构上均有效
- 深度可分离卷积（MobileNetV2）的加速比略低（点卷积的稀疏模式特性不同）
- 所有模型的精度损失均控制在2%以内

### 4.3 消融实验

#### 4.3.1 列向压缩 vs 其他格式

| 存储格式 | PE利用率(50%稀疏) | 控制逻辑复杂度 | 部分和归约效率 |
|---------|------------------|--------------|--------------|
| 密集 | 50% | 低 | 高 |
| CSR | 65% | 高 | 低 |
| 列向压缩 | **80%** | **中** | **高** |

**关键发现**：列向压缩在PE利用率和控制复杂度之间取得了最佳平衡。

#### 4.3.2 硬件感知剪枝的贡献

| 剪枝方法 | 50%稀疏度下精度 | 列可移除率 |
|---------|---------------|----------|
| 随机非结构化剪枝 | 91.5% | 30% |
| 标准结构化剪枝 | 90.5% | 50% |
| 硬件感知剪枝(本文) | **92.5%** | **45%** |

**关键发现**：硬件感知剪枝在精度和列可移除率之间达到了更好的平衡。

#### 4.3.3 PE阵列规模的影响

| PE阵列大小 | LUT利用率 | 最大频率 | 吞吐量(50%稀疏) |
|-----------|----------|---------|---------------|
| 4×4 | 15% | 280 MHz | 500 img/s |
| 8×8 | 35% | 250 MHz | 1800 img/s |
| 16×16 | 70% | 200 MHz | 4500 img/s |

**关键发现**：
- 更大的PE阵列提供更高的绝对吞吐量
- 但最大频率随规模增加而下降（路由延迟增加）
- 存在最优配置点，取决于FPGA资源和目标模型

## 5. 局限性与未来展望

### 5.1 局限性

#### 5.1.1 仅限于卷积层

SparHiXcel-v2主要针对卷积层优化：
- 全连接层的列向压缩效果有限（通常已经是1D）
- 注意力机制的稀疏支持未涉及
- 其他操作（如池化、BN）未优化

#### 5.1.2 FPGA频率限制

受限于FPGA的路由网络和DSP单元，SparHiXcel-v2的最高工作频率（约200-280MHz）远低于ASIC实现（通常500MHz-1GHz）：
- 限制了绝对性能上限
- 动态功耗较高（更多周期完成相同计算）
- 相比ASIC方案的竞争劣势

#### 5.1.3 配置搜索空间

PE阵列大小、MUX-T参数、FSUM-Store单元数等设计参数构成巨大的配置空间：
- 手动调优耗时
- 不同模型/数据集的最优配置不同
- 缺乏自动化的设计空间探索工具

#### 5.1.4 评估范围

实验主要在CIFAR-10上验证，ImageNet的评估相对有限：
- 小数据集的结论可能不完全适用于大规模数据
- 未在真实边缘设备上部署验证
- 缺少与其他FPGA加速器的全面比较

### 5.2 未来展望

#### 5.2.1 扩展到Transformer架构

将列向压缩思想扩展到Transformer的注意力机制：
- 注意力矩阵的稀疏模式通常具有结构性（如局部注意力、稀疏注意力）
- 设计支持可变注意力跨度的高效硬件
- 结合低秩近似和稀疏化

#### 5.2.2 自动化设计空间探索

开发自动化的DSE（Design Space Exploration）工具：
- 给定目标模型和FPGA资源约束，自动搜索最优配置
- 使用强化学习或贝叶斯优化进行多目标优化
- 考虑功耗-性能-精度的联合优化

#### 5.2.3 多精度支持

扩展SparHiXcel-v2支持混合精度推理：
- 不同层使用不同位宽（INT8/INT4/INT2）
- 动态精度调整（如MotionVQ中的状态感知精度）
- 与量化感知训练的联合优化

#### 5.2.4 多FPGA扩展

对于超大模型，探索多FPGA并行加速：
- 层间并行（pipeline）
- 层内并行（模型并行）
- 稀疏感知的负载均衡

## 6. 学术启发

### 6.1 可迁移思路

#### 6.1.1 中间地带设计哲学

本文的核心设计哲学——在完全灵活和完全规则之间寻找中间地带——可以广泛迁移：

1. **存储系统**：在完全关联和直接映射之间寻找组相联的平衡
2. **调度策略**：在静态调度和完全动态调度之间寻找半静态调度
3. **网络拓扑**：在总线和全连接之间寻找各种间接网络拓扑
4. **数据精度**：在FP32和INT8之间探索多种混合精度方案

#### 6.1.2 数据流感知的算法设计

本文的硬件感知剪枝算法展示了"以数据流特性指导算法设计"的思路：
- 了解目标硬件的数据流特性
- 设计算法使数据流模式与硬件特性匹配
- 联合优化算法输出和硬件执行效率

这一思路可应用于：
- 内存感知的算法设计（减少缓存未命中）
- 并行感知的算法设计（最大化并行度）
- 通信感知的分布式算法设计（减少网络传输）

#### 6.1.3 渐进式结构简化

列向压缩的两阶段过程（行内压缩→列移除）展示了渐进式结构简化的方法论：
- 阶段一：在保持约束条件下局部优化
- 阶段二：利用阶段一的结果进行更激进的简化
- 每阶段都可逆且保持正确性

### 6.2 实验设计借鉴

#### 6.2.1 多维度稀疏度评估

本文在30%、50%、70%、90%多个稀疏度级别上评估，揭示了方法在不同稀疏度下的表现规律：
- 避免仅在"甜点"稀疏度展示结果
- 全面展示方法的适用范围和局限性
- 为实际应用中的稀疏度选择提供依据

#### 6.2.2 算法-硬件联合消融

本文不仅消融硬件参数，还消融算法参数（如剪枝策略），展示了协同设计的价值：
- 仅优化硬件：可能受限于算法产生的稀疏模式
- 仅优化算法：可能产生硬件不友好的稀疏模式
- 联合优化：找到真正的帕累托最优解

#### 6.2.3 真实FPGA实现验证

相比纯模拟或RTL仿真，本文在真实FPGA上实现并验证：
- 考虑了实际布局布线的影响
- 测量了真实功耗（而非估计）
- 验证了在真实设备上的可操作性

#### 6.2.4 开源代码发布

本文将源代码发布在GitHub上（https://github.com/INRS-ECCoLe/SparHiXcel）：
- 增强了结果的可重复性
- 促进了社区后续研究
- 降低了其他研究者进入该领域的门槛
