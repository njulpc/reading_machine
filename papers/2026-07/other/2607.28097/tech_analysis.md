# 从专家归约到行为发散：追踪稀疏 MoE 推理中的数值状态

> **论文标题**: From Expert Reduction to Behavioral Divergence: Tracing Numerical State through Sparse MoE Inference
> **作者**: Tianyang Zhu
> **arXiv**: https://arxiv.org/abs/2607.28097
> **发表日期**: 2026-07-30
> **类别**: cs.LG
> **页数**: 32 pages, 3 figures

---

## 1. 核心速览

- **研究主题**: 稀疏混合专家（Sparse MoE）模型中，数学上等价的专家归约顺序（expert-reduction orders）如何因数值精度差异导致可观测的不同执行结果。论文在原生 DeepSeek-V4-Flash 上通过冻结局部 MoE 状态、仅变化聚合语义，系统隔离并追踪了从数值状态到行为发散的完整因果链。
- **一句话总结**: 在稀疏 MoE 推理中，数学等价的专家归约顺序因操作数表示精度与累加器精度的分离而产生行为发散——相同的 token 不意味着相同的自回归状态，发散可以跨越 token 边界存活并在后续变得可见，这使得专家操作数转换、累加器精度和归约顺序成为稀疏 MoE 运行时和硬件后端的数值兼容性契约的组成部分。

## 2. 研究背景与动机 (Background & Motivation)

### 2.1 稀疏 MoE 模型的数值挑战

稀疏混合专家（Sparse Mixture-of-Experts, MoE）模型已成为大规模语言模型的主流架构。在 MoE 推理中，每个 token 由路由器分配到若干专家，各专家的输出需要被归约（聚合）为最终结果。这一归约过程在数学上是简单的加权求和，但在实际数值实现中涉及复杂的精度问题：

- **操作数表示（operand representation）**：专家输出的数值表示精度（如 FP32、FP16、BF16 等）。
- **累加器精度（accumulator precision）**：在归约求和过程中，中间累加结果的精度。
- **归约顺序（reduction order）**：多个专家输出的求和顺序。

在精确算术下，加法满足交换律和结合律，因此归约顺序不影响结果。但在有限精度浮点运算中，不同的归约顺序会产生不同的舍入误差，导致最终结果存在微小差异。

### 2.2 数学等价但行为不同

论文的核心观察是：**数学上等价的专家归约顺序可以产生可观测的不同稀疏 MoE 执行结果**。这一现象虽然在数值分析中是已知的（浮点加法不满足结合律），但在大规模 MoE 模型的实际推理中，其影响程度和传播机制此前未被系统研究。

关键问题包括：
- 微小的数值差异如何通过自回归生成过程被放大？
- 不同的归约方案在多大规模上导致不同的生成结果？
- 数值发散在模型内部的哪个位置产生、如何传播？
- 这些发现对 MoE 模型的部署和硬件后端有什么实际影响？

### 2.3 DeepSeek-V4-Flash 作为研究对象

论文选择原生 DeepSeek-V4-Flash 作为研究对象，这是一个实际部署的大规模稀疏 MoE 模型。选择原生模型（而非简化模型）的意义在于：
- 研究结果直接适用于实际部署场景。
- 原生模型的复杂性与真实世界一致，不存在简化带来的偏差。
- 可以直接与原生推理路径进行逐位对比验证。

### 2.4 动机总结

论文的动机是系统性地追踪稀疏 MoE 推理中数值状态的传播路径，从最初的专家归约数值差异，到中间隐藏状态的发散，再到最终生成文本的分歧。通过精确的实验控制，论文旨在建立 MoE 数值兼容性的理论基础，为运行时和硬件后端的设计提供指导。

## 3. 核心方法与创新点 (Methodology & Innovations)

### 3.1 实验隔离设计：冻结状态，仅变聚合语义

论文的实验设计极为精巧：**冻结局部 MoE 状态，仅变化聚合语义（aggregation semantics）**。这意味着：
- 所有专家的输入和输出完全相同（冻结状态）。
- 唯一变化的是这些专家输出如何被归约（聚合语义）。
- 通过这种隔离，排除了路由、专家计算等其他因素的干扰，将观察到的差异完全归因于归约数值差异。

### 3.2 四种归约方案：操作数表示与累加器精度的分离

论文定义了四种归约方案（P32、A、B、C），它们在**操作数表示精度**和**累加器精度**两个维度上进行分离：

- **P32**：某种基准精度方案（可能是全 FP32）。
- **A 模式**：一种操作数/累加器精度组合。
- **B 模式**：另一种操作数/累加器精度组合。
- **C 方案**：一种特殊方案，被证明能保持与原生 MoE 的逐位一致。

这四种方案的设计使得论文能够独立分析操作数精度和累加器精度各自的影响，以及它们的交互效应。

### 3.3 层-5 分叉的精细分析

论文在第 5 层（layer-5）的一个分叉点进行了极其精细的分析：

#### A 模式
- **720 种 A 模式归约顺序**产生了 **10 个延续盆地（continuation basins）**。
- 这意味着 720 种数学等价的归约顺序最终收敛到 10 种不同的生成行为。

#### B 模式
- **720 种 B 模式归约顺序**形成了 **360 个精确结构类（exact structural classes）**和 **11 个盆地**。
- B 模式比 A 模式产生了更细粒度的分化（360 个结构类 vs 10 个盆地），表明 B 模式的精度组合对归约顺序更敏感。

这一结果深刻揭示了：即使是数学等价的操作，在不同的精度方案下，其对归约顺序的敏感性也不同。

### 3.4 语义级发散：中文提示的案例

在一个中文提示下，B 类分裂为三种截然不同的语义延续：
- **202 个裁员（layoffs）**延续
- **113 个招聘（hiring）**延续
- **45 个其他（other）**延续

这一结果是论文最引人注目的发现之一：完全相同的输入和相同的专家输出，仅因归约顺序的数值差异，就导致了截然相反的语义输出（裁员 vs 招聘）。这证明了数值发散不仅仅是理论上的微小差异，而是可以导致**语义级别的行为分歧**。

### 3.5 Maximum-L-infinity 分支选择的判别能力

论文使用最大 L-无穷范数（Maximum-L-infinity）的 B 分支选择来评估发散的判别能力：
- 在 50 个提示中，B 分支选择在 **8 个 token** 处分离了 **12 个**提示。
- 在 **16 个 token** 处分离了 **24 个**提示。
- 在 **32 个 token** 处分离了 **36 个**提示。

这表明随着生成长度的增加，数值发散影响的提示比例逐渐增大（从 24% 到 72%），验证了自回归生成过程中的误差累积效应。

### 3.6 192 条持久轨迹的系统性比较

论文对每种方案进行了 **192 条持久轨迹（persistent trajectories）**的系统性比较：

- **P32、A 和 B 方案**：改变了**每一条**原生参考路由轨迹。即这三种方案的数值差异足以影响所有轨迹的路由决策。
- **C 方案**：**保持了路由、token 序列和文本的完全一致**。即 C 方案在数值上与原生 MoE 完全兼容。

C 方案的这一特性使其成为验证数值兼容性的"黄金标准"。

### 3.7 C 方案的逐位验证

论文对 C 方案进行了独立的 192 条轨迹检查，验证了其与原生 MoE 在以下四个层面的**逐位一致（bitwise agreement）**：
1. **原生 MoE 状态**
2. **post-mHC 状态**（mHC 后状态）
3. **next-router 状态**（下一路由器状态）
4. **LM 状态**（语言模型状态）

这一逐位验证是极为严格的——不仅要求最终输出相同，还要求所有中间状态的每一位都完全一致。这为 C 方案的数值兼容性提供了确凿证据。

### 3.8 受控 B 分支的精确重建

对于一条受控的 B 分支，论文进行了**精确的 post-mHC 端点重建（exact post-mHC endpoint reconstruction）**：
- 通过精确重建 post-mHC 端点，成功**复现了测量的下游轨迹**。
- 这证明了 post-mHC 状态是下游行为的充分决定因素——给定精确的 post-mHC 状态，下游轨迹是确定性的。

### 3.9 跨 token 边界的持久状态重建

在下一个解码边界处，论文进行了**精确 FP64 重建（exact FP64 reconstruction）**：
- 对分支的完整持久状态进行 FP64 精度重建。
- 在给定相同自然生成的下一输入的条件下，获得了以下七个步骤的完全一致：
  - **301 个下游 post-mHC 状态**
  - **301 个持久状态检查点**
  - **301 个路由**
  - **301 个预测**
  - **文本**（七步）

这一结果具有重要的理论意义：它证明了**完整持久状态是跨 token 延续的边界**——给定完整的持久状态和下一输入，未来七步的所有状态和输出都是确定性的。

### 3.10 关键边界识别

基于上述控制实验，论文识别出两个关键边界：

1. **post-mHC 作为 token 内边界（intra-token boundary）**：post-mHC 状态决定了当前 token 处理内的下游行为。
2. **完整持久状态作为跨 token 延续边界（cross-token continuation boundary）**：完整持久状态决定了跨 token 的自回归延续。

### 3.11 核心洞察：相同 token 不意味着相同状态

论文最深刻的洞察是：**相同的 token 不意味着相同的自回归状态**。数值发散可以：
- 在当前 token 的生成中不产生可见差异（生成相同的 token）。
- 但在持久状态中留下痕迹。
- 跨越 token 边界存活。
- 在后续 token 的生成中变得可见。

这一发现挑战了常见的"如果输出 token 相同则状态相同"的假设，揭示了自回归生成中隐藏状态传播的复杂性。

### 3.12 数值兼容性契约

基于所有发现，论文提出：**专家操作数转换、累加器精度和归约顺序应成为稀疏 MoE 运行时和硬件后端的数值兼容性契约（numerical compatibility contract）的组成部分**。这意味着：
- MoE 推理框架需要明确定义和文档化其数值处理方案。
- 硬件后端需要遵守数值兼容性规范，确保不同实现产生一致的结果。
- 模型部署时需要验证数值兼容性，避免因后端差异导致的行为分歧。

## 4. 实验设计与结果 (Experiments & Results)

### 4.1 实验设置

- **模型**: 原生 DeepSeek-V4-Flash（实际部署的大规模稀疏 MoE 模型）。
- **实验方法**: 冻结局部 MoE 状态，仅变化聚合语义。
- **归约方案**: 四种方案（P32、A、B、C），分离操作数表示与累加器精度。
- **验证方法**: 逐位比较、精确重建、持久轨迹追踪。
- **精度控制**: FP64 用于精确重建实验。

### 4.2 层-5 分叉结果

| 指标 | A 模式 | B 模式 |
|------|--------|--------|
| 归约顺序数 | 720 | 720 |
| 精确结构类 | - | 360 |
| 延续盆地 | 10 | 11 |

B 模式形成了 360 个精确结构类（远多于 A 模式的 10 个盆地），表明 B 模式对归约顺序更加敏感，产生了更细粒度的行为分化。

### 4.3 中文提示的语义分裂

在一个中文提示下，B 类的 360 个结构类分裂为：
- **202 个裁员（layoffs）延续**（56.1%）
- **113 个招聘（hiring）延续**（31.4%）
- **45 个其他（other）延续**（12.5%）

裁员与招聘是完全相反的语义方向，这一结果证明了数值发散可以导致语义级别的行为分歧。

### 4.4 Maximum-L-infinity 分离能力

| Token 数 | 分离的提示数（共 50） | 分离比例 |
|----------|---------------------|---------|
| 8 | 12 | 24% |
| 16 | 24 | 48% |
| 32 | 36 | 72% |

分离比例随生成长度单调增加，验证了自回归过程中的误差累积效应。

### 4.5 192 条持久轨迹结果

| 方案 | 路由轨迹变化 | 路由保持 | Token 序列保持 | 文本保持 |
|------|-------------|---------|--------------|---------|
| P32 | 每条都变 | 否 | 否 | 否 |
| A | 每条都变 | 否 | 否 | 否 |
| B | 每条都变 | 否 | 否 | 否 |
| C | 无变化 | 是 | 是 | 是 |

只有 C 方案保持了与原生 MoE 的完全一致，包括路由、token 序列和文本。

### 4.6 C 方案逐位验证

C 方案在 192 条轨迹上与原生 MoE 在四个层面实现逐位一致：
- 原生 MoE 状态：逐位一致
- post-mHC 状态：逐位一致
- next-router 状态：逐位一致
- LM 状态：逐位一致

### 4.7 受控 B 分支重建

- **post-mHC 端点重建**：精确重建后复现了测量的下游轨迹，证明 post-mHC 是 token 内行为的充分决定因素。
- **FP64 完整持久状态重建**：在下一解码边界处，FP64 重建获得了 301 个下游 post-mHC 状态、301 个持久状态检查点、301 个路由、301 个预测和文本在七个步骤上的完全一致，证明完整持久状态是跨 token 延续的边界。

### 4.8 结果总结

论文的实验结果形成了一个完整的因果链：
1. **数值差异的起源**：不同归约顺序在有限精度下产生不同的舍入误差。
2. **差异的传播**：舍入误差通过 MoE 层传播到 post-mHC 状态。
3. **行为分歧的出现**：post-mHC 状态的差异影响路由决策和 token 生成。
4. **分歧的持久化**：持久状态中的差异跨越 token 边界存活，在后续生成中变得可见。
5. **语义级影响**：在极端情况下，数值差异导致截然相反的语义输出（裁员 vs 招聘）。

## 5. 局限性与未来展望 (Limitations & Future Work)

### 5.1 单模型研究的局限

论文的研究基于 DeepSeek-V4-Flash 单一模型。不同 MoE 架构（如不同专家数量、不同路由策略、不同归约结构）的数值敏感性可能不同。未来可以：
- 在更多 MoE 架构上验证研究发现（如 Mixtral、GLaM 等）。
- 研究架构特征（如专家数量、Top-K 值）对数值敏感性的影响。
- 建立跨架构的数值兼容性基准。

### 5.2 硬件后端的扩展验证

论文聚焦于软件层面的归约方案，但实际部署中硬件后端（如 GPU、TPU、专用 ASIC）的浮点实现也可能引入数值差异。未来可以：
- 在不同硬件后端上验证数值兼容性。
- 研究硬件级浮点实现差异对 MoE 行为的影响。
- 建立硬件后端的数值兼容性认证标准。

### 5.3 C 方案的推广

C 方案被证明与原生 MoE 逐位一致，但其具体实现细节（操作数精度、累加器精度、归约顺序）在摘要中未完全明确。未来可以：
- 详细描述 C 方案的具体实现，使其成为标准参考。
- 研究 C 方案在不同硬件上的可实现性和效率。
- 探索是否存在其他与原生 MoE 逐位一致的方案。

### 5.4 量化与压缩的交互

论文关注的是浮点精度下的归约顺序差异。当 MoE 模型进一步进行量化或压缩时，数值敏感性可能更加复杂。未来可以：
- 研究量化 MoE 模型的数值兼容性问题。
- 探索压缩（如论文 7 揭示的 SVD 截断）与归约顺序的交互效应。
- 建立压缩 MoE 模型的数值安全边界。

### 5.5 发散缓解策略

论文诊断了数值发散的存在和机制，但未提出缓解策略。未来可以：
- 设计数值稳定的 MoE 归约算法，减少对归约顺序的敏感性。
- 研究混合精度策略，在关键位置使用高精度以减少发散。
- 探索路由器的数值鲁棒性训练，使路由决策对微小数值差异不敏感。

### 5.6 跨 token 发散的理论分析

论文发现发散可以跨越 token 边界存活，但对这一现象的理论分析仍不充分。未来可以：
- 建立数值发散在自回归生成中传播的理论模型。
- 分析哪些模型组件（注意力、FFN、路由器）对数值发散最敏感。
- 研究发散的累积规律（线性、指数还是其他）。

### 5.7 实际部署影响

论文的发现对实际部署有重要影响，但实际场景中的复杂性（如批处理、流水线并行、张量并行）可能引入额外的数值差异。未来可以：
- 研究分布式推理中的数值兼容性问题。
- 建立端到端的数值兼容性验证流程。
- 开发自动化数值兼容性检测工具。

## 6. 学术启发 (Takeaways for My Research)

### 6.1 数学等价不等于数值等价

论文最根本的启发是：**在有限精度浮点运算中，数学等价的操作不一定是数值等价的**。这一原则虽然简单，但在深度学习实践中经常被忽视：
- 我们通常假设加法的交换律和结合律在浮点运算中成立，但实际上它们不成立。
- 在 MoE 归约、注意力计算、矩阵乘法等场景中，操作顺序和精度选择都会影响结果。
- 这要求我们在设计模型和推理系统时，始终考虑数值精度的影响。

### 6.2 自回归生成中的误差放大

论文揭示了自回归生成中数值误差的放大机制：
- 微小的数值差异通过隐藏状态传播。
- 差异在路由决策处可能被放大（因为路由是离散的、阈值敏感的）。
- 差异可以跨越 token 边界存活，在后续生成中变得可见。
- 在极端情况下，差异导致语义级别的行为分歧（裁员 vs 招聘）。

这一发现对模型压缩研究有重要启示：压缩引入的微小数值差异在自回归生成中可能被放大，导致显著的行为变化。这要求压缩评估不仅要关注单步误差，还要关注多步生成中的误差累积。

### 6.3 数值边界的精确识别

论文通过精确重建实验识别了两个关键边界：
- **post-mHC 作为 token 内边界**：决定了当前 token 处理内的所有下游行为。
- **完整持久状态作为跨 token 边界**：决定了自回归延续的所有未来状态。

这一边界识别对模型调试和验证具有重要价值：
- 如果要验证两个 MoE 实现的等价性，只需比较 post-mHC 状态和完整持久状态。
- 如果要定位数值发散的源头，可以在 post-mHC 边界处进行检查。
- 这为建立数值兼容性验证协议提供了精确的检查点。

### 6.4 "相同 token 不等于相同状态"的深刻含义

论文的核心洞察——**相同的 token 不意味着相同的自回归状态**——对深度学习研究有深远影响：
- 在评估模型等价性时，仅比较输出 token 是不够的，还需要比较内部状态。
- 在知识蒸馏中，学生模型可能生成与教师模型相同的 token，但内部状态可能存在差异，这些差异在后续生成中可能变得可见。
- 在模型压缩中，压缩模型可能在短期生成中与原始模型一致，但在长期生成中发散。这要求压缩评估使用足够长的生成序列。

### 6.5 对 MoE 压缩的特殊启示

论文的发现对 MoE 模型压缩有特殊启示：
- MoE 模型的专家归约是一个数值敏感操作，压缩（如专家剪枝、专家量化）可能放大数值敏感性。
- 压缩 MoE 模型时，需要特别注意归约顺序和精度选择，确保数值兼容性。
- 压缩评估应包括多步生成的稳定性测试，而不仅仅是单步困惑度或准确率。

### 6.6 数值兼容性契约的概念

论文提出的"数值兼容性契约"概念对工业实践有重要价值：
- 它将数值处理从"实现细节"提升为"接口规范"。
- 不同的 MoE 运行时和硬件后端可以通过遵守相同的契约来保证行为一致。
- 这为 MoE 模型的可移植部署提供了基础。

### 6.7 实验方法论的启发

论文的实验方法论极为严谨，值得借鉴：
- **隔离设计**：冻结所有其他变量，仅变化感兴趣的因素。
- **逐位验证**：不仅比较最终输出，还比较所有中间状态的每一位。
- **精确重建**：通过 FP64 重建来验证状态传播的确定性。
- **大规模轨迹**：192 条轨迹的系统性比较，确保结论的统计可靠性。
- **因果链追踪**：从数值差异的起源到行为分歧的出现，追踪完整的因果链。

### 6.8 对模型压缩研究的整体启示

结合本论文和论文 7（Fidelity Is Not Safety）的发现，模型压缩研究面临一个共同主题：**微小的数值变化（无论来自压缩算子还是归约顺序）可能在特定场景中被放大，导致显著的行为差异**。这要求：
- 压缩评估需要关注长期行为稳定性，而不仅仅是短期指标。
- 压缩方法的设计需要考虑数值鲁棒性，而不仅仅是参数效率。
- 压缩模型的安全评估需要包括数值敏感性分析。

---

> **总结**: 论文 "From Expert Reduction to Behavioral Divergence" 在原生 DeepSeek-V4-Flash 上系统研究了稀疏 MoE 推理中数学等价专家归约顺序的数值发散问题。通过冻结局部 MoE 状态、仅变化聚合语义的隔离设计，论文定义了四种归约方案（P32、A、B、C），发现 720 种 B 模式归约顺序形成 360 个精确结构类和 11 个延续盆地，在一个中文提示下分裂为 202 个裁员、113 个招聘和 45 个其他延续。Maximum-L-infinity 分析显示 50 个提示中 36 个在 32 个 token 处被分离。192 条轨迹的系统性比较证明只有 C 方案与原生 MoE 逐位一致。精确 FP64 重建验证了 301 个下游状态在七步上的完全一致。这些结果识别了 post-mHC 为 token 内边界、完整持久状态为跨 token 边界，揭示了"相同 token 不等于相同状态"的深刻洞察，并提出了专家操作数转换、累加器精度和归约顺序作为 MoE 数值兼容性契约的组成部分。
