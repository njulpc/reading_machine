# CoMem: 沿层轴组织长上下文记忆的深度分工方法

> **论文标题**: Understanding Is Done Early: A Depth Division of Labor in Large Language Models and Its Use for Unbounded-Context Memory
> **作者**: Hanzuo Liu, Xuan Qi, Chunyu Liu, Haotian Zhong, Yulong Wang, Rayying, Key, Alex Lamb, Mingyu Gao
> **arXiv**: https://arxiv.org/abs/2607.28263
> **发表日期**: 2026-07-30
> **类别**: cs.CL
> **页数**: 19 pages, 4 figures, 27 tables. Submitted to ACL Rolling Review

---

## 1. 核心速览

- **研究主题**: 大语言模型（LLM）Transformer 深度方向上的"分工"现象及其在无界上下文记忆（Unbounded-Context Memory）中的应用。论文提出 CoMem（Comprehension Memory），一种沿层轴（layer axis）而非仅沿 token 轴组织长上下文记忆的新范式。
- **一句话总结**: 利用 Transformer 浅层/中层负责语义理解、上层负责预测特化的深度分工特性，CoMem 仅将每个上下文块编码至中间层并缓存残差状态，查询时检索固定数量的缓存状态后重计算上层，从而实现读取计算量与内存均独立于存储上下文长度的无界上下文记忆系统。

---

## 2. 研究背景与动机 (Background & Motivation)

### 2.1 长上下文处理的核心瓶颈

当前大语言模型在处理长上下文时面临两个根本性挑战：**计算复杂度**和**内存占用**随上下文长度线性或超线性增长。传统的全上下文 KV-Direct 方法需要将所有 token 的 KV cache 保留在显存中，当上下文达到数十万 token 时，显存需求和 prefill 计算量均变得不可承受。例如，论文在 NVIDIA H20 上的实验显示，全上下文 KV-Direct 在 128k 上下文下需要 89.36 GB 显存，这在实际部署中几乎不可行。

### 2.2 现有方法的局限

现有的长上下文方法主要沿 token 轴进行优化，包括：
- **滑动窗口注意力**：丢弃早期 token 的 KV cache，但会损失长距离依赖信息。
- **KV cache 压缩/驱逐**：基于重要性评分选择性保留 KV 对，但在超长上下文下仍面临退化。
- **检索增强方法**：将外部文档检索后拼接到上下文中，但每次查询的 prefill 计算量仍与检索到的上下文长度成正比。

这些方法共同的问题是：它们都将 Transformer 的所有层视为同质的处理单元，没有利用不同深度层在功能上的差异。

### 2.3 深度分工的发现

论文的核心观察是：**Transformer 的深度并未被均匀使用**。具体而言：
- **浅层和中层**负责构建语义表示（semantic representations），即"理解"工作主要在这些层完成。
- **上层**越来越专注于将这些表示特化用于预测（prediction specialization）。

这一发现意味着，上下文的"理解"在中间层就已经基本完成，上层的计算更多是查询条件化的预测特化。如果我们将上下文的理解结果（中间层的残差状态）缓存下来，而仅在查询时重计算上层，就能实现读取计算量和内存与存储上下文长度无关的目标。

### 2.4 动机总结

论文的动机可以概括为：**长上下文记忆的组织不应仅沿 token 轴进行，还应沿层轴进行**。通过将上下文的理解（浅中层）与预测特化（上层）解耦，可以在不损失理解质量的前提下，大幅降低长上下文场景下的计算和内存开销。

## 3. 核心方法与创新点 (Methodology & Innovations)

### 3.1 深度分工的实证发现

论文首先通过实验验证了 Transformer 中深度的非均匀使用模式。具体而言，论文观察到：
- 低层和中层主要参与语义表示的构建，这些层的计算不依赖于具体的查询（query-independent）。
- 上层越来越专注于预测特化，这些层的计算高度依赖于具体查询（query-conditioned）。

这一发现为将上下文处理沿深度方向分解提供了理论基础：上下文块只需被处理到中间层即可获得充分的语义表示，上层的预测特化可以延迟到查询阶段进行。

### 3.2 CoMem 的核心架构

CoMem 的核心设计包含三个关键步骤：

1. **中间层写入（Write through intermediate layer）**：每个上下文块仅通过 Transformer 的中间层进行编码，而不是通过完整的所有层。这意味着每个上下文块的 KV cache 只存储到中间层为止的残差状态（residual states），上层的 KV cache 不被存储。

2. **固定数量检索（Retrieve a fixed number of cached residual states）**：在查询阶段，根据查询条件从所有缓存的中间层残差状态中检索固定数量的状态。由于检索数量是固定的，读取计算量不随存储上下文长度增长。

3. **上层重计算（Recompute query-conditioned upper layers）**：将检索到的中间层残差状态组成一个"pack"，然后从中间层开始重计算上层。上层的计算是查询条件化的，因此这一步确保了预测的准确性。

### 3.3 关键创新：计算与内存的长度无关性

CoMem 的核心创新在于：**对于固定的检索预算，模型侧的读取计算量和内存均独立于存储上下文的长度**。这意味着无论存储了多少上下文块，每次查询的计算和内存开销都是恒定的。这是一个本质性的突破，使得无界上下文记忆成为可能。

### 3.4 自蒸馏 LoRA 训练策略

CoMem 的训练策略具有高度简洁性：
- **骨干网络冻结**：基础模型 Qwen3-8B 的骨干完全冻结，不进行任何参数更新。
- **Rank-32 自蒸馏 LoRA**：旗舰配置仅在 PG19 纯文本数据上训练一个 rank-32 的自蒸馏 LoRA 适配器。自蒸馏的目标是让中间层截断后的表示尽可能接近完整模型的表示。
- **无适配器分支**：论文还报告了一个完全不使用任何适配器的分支（adapter-free arm），用于评估纯截断方法的性能。

这种训练策略的优势在于：
- 训练数据需求极低（仅需 PG19 纯文本）。
- 训练成本极低（仅训练一个小型 LoRA）。
- 不需要特定任务的标注数据。

### 3.5 统一的无聊天模板协议

论文采用了统一的 chat-template-free 评估协议，在 continued-trained 的 Qwen3-8B base LM 上进行评估。这一设计选择避免了聊天模板对评估结果的干扰，使得不同方法的比较更加公平。

### 3.6 深度扫描与自蒸馏修复

论文通过受控的深度扫描（controlled depth sweeps）实验发现：
- **更深的缓存**（即在更早的中间层截断）可以降低每次查询的重计算量，但会引入保真度损失（fidelity loss），因为截断了更多对理解至关重要的层。
- **自蒸馏**能够显著修复这种保真度损失，使得在更深层截断时仍能保持良好的性能。

这一发现为实际部署中的深度选择提供了灵活性：可以根据计算预算选择不同的截断深度，并通过自蒸馏来弥补性能损失。

## 4. 实验设计与结果 (Experiments & Results)

### 4.1 实验设置

- **基础模型**: Qwen3-8B base LM，经过 continued training。
- **评估协议**: 统一的 chat-template-free 协议。
- **训练数据**: PG19 纯文本。
- **训练参数**: 骨干冻结，仅训练 rank-32 自蒸馏 LoRA。
- **硬件**: NVIDIA H20 GPU（用于效率评估）。

### 4.2 主要基准测试结果

#### RULER 基准
- **CoMem**: 97.05
- **全上下文 KV-Direct**: 34.59

CoMem 在 RULER 上的表现远超全上下文 KV-Direct，这一结果令人惊讶。全上下文方法理论上应该能够看到所有上下文信息，但其 34.59 的低分表明，在超长上下文场景下，全上下文方法可能因为注意力稀释或位置编码退化等问题而表现不佳。CoMem 通过固定数量的检索和上层重计算，反而更有效地利用了上下文信息。

#### LoCoMo 基准（对话记忆）
- **CoMem**: 38.27
- **全上下文 KV-Direct**: 34.59

在对话记忆任务 LoCoMo 上，CoMem 同样优于全上下文方法。论文进一步验证了这一优势的稳健性：
- 对话聚类重采样（conversation-cluster resampling）后优势依然存在。
- 独立评判者（independent judge）评估下优势依然存在。

### 4.3 额外长上下文和长文档任务

论文在额外的长上下文和长文档任务上的结果揭示了两个重要发现：
- **有界检索的好处**：固定数量的检索在多种任务上表现良好，验证了"不需要看到所有上下文"的核心假设。
- **窗口内压缩税**：在需要利用当前窗口内完整上下文的任务上，CoMem 的中间层截断会引入一定的性能损失，即"压缩税"。这表明 CoMem 在某些任务类型上存在适用性边界。

### 4.4 效率评估

在 NVIDIA H20 上 128k 上下文的 adapter-free 效率控制实验中：
- **显存使用**: CoMem 仅需 18.26 GB，而全上下文 KV-Direct 需要 89.36 GB，节省约 79.6%。
- **Prefill 加速**: CoMem 实现 7.83 倍的 prefill 速度提升。

这些数字表明，CoMem 在效率方面具有显著优势，使其能够在资源受限的环境中处理超长上下文。

### 4.5 深度扫描实验

受控深度扫描实验的结果表明：
- 随着截断深度增加（即缓存更少层的 KV），每次查询的重计算量降低。
- 但同时，截断引入的保真度损失增加。
- 自蒸馏 LoRA 能够显著修复更深层截断带来的保真度损失，在计算效率和性能之间提供更好的折衷。

### 4.6 结果总结

| 指标 | CoMem | 全上下文 KV-Direct |
|------|-------|-------------------|
| RULER | 97.05 | 34.59 |
| LoCoMo | 38.27 | 34.59 |
| 显存 (128k, H20) | 18.26 GB | 89.36 GB |
| Prefill 加速比 | 7.83x | 1x (基准) |

## 5. 局限性与未来展望 (Limitations & Future Work)

### 5.1 窗口内压缩税

论文坦诚地指出，CoMem 在需要利用当前窗口内完整上下文的任务上存在"压缩税"。这是因为中间层截断不可避免地丢失了上层对当前窗口 token 的精细处理。对于需要精确窗口内推理的任务（如代码补全、数学计算等），这一压缩税可能较为显著。未来的工作可以探索自适应的截断深度选择，根据任务类型动态决定是否进行层轴压缩。

### 5.2 检索预算的固定性

CoMem 使用固定数量的检索，这在某些场景下可能不是最优的。不同的查询可能需要不同数量的上下文信息。例如，简单的查询可能只需要少量检索结果，而复杂的推理查询可能需要更多。未来可以探索自适应检索预算机制，在保持计算效率的同时提升性能。

### 5.3 自蒸馏的训练数据依赖

虽然 CoMem 的自蒸馏 LoRA 仅在 PG19 纯文本上训练，训练成本极低，但不同领域的数据分布可能影响截断表示的质量。未来可以研究多领域数据的自蒸馏策略，或者探索领域自适应的截断方法。

### 5.4 深度分工的通用性验证

论文的深度分工发现主要基于 Qwen3-8B 模型。不同架构（如不同大小的模型、不同注意力机制的模型）是否也表现出类似的深度分工模式，需要进一步验证。如果深度分工是 Transformer 的普遍特性，那么 CoMem 的方法可以广泛推广；如果它是特定模型/规模的现象，则需要针对不同模型调整截断深度。

### 5.5 与其他压缩方法的结合

CoMem 沿层轴进行压缩，而传统方法沿 token 轴压缩。两者在原理上是正交的，未来可以探索将 CoMem 与 token 级 KV cache 压缩方法结合，进一步降低内存和计算开销。

### 5.6 长期对话场景的扩展

LoCoMo 上的结果表明 CoMem 在对话记忆方面有优势，但实际的长对话场景可能更加复杂，涉及多轮对话中的动态上下文管理、遗忘机制等。未来可以将 CoMem 扩展到更真实的长期对话助手场景。

## 6. 学术启发 (Takeaways for My Research)

### 6.1 深度轴作为新的优化维度

CoMem 最核心的启发是：**将 Transformer 的深度轴作为长上下文优化的新维度**。传统方法几乎都沿 token 轴进行优化（剪枝、压缩、检索），而 CoMem 展示了沿层轴优化的巨大潜力。这一思路可以推广到其他场景：
- 推理加速：是否可以对不同复杂度的查询使用不同的计算深度？
- 模型压缩：是否可以沿深度方向进行结构化压缩？
- 多任务学习：不同任务是否可以利用不同深度的表示？

### 6.2 "理解"与"预测"的解耦

CoMem 的深度分工发现为"理解"与"预测"的解耦提供了实证基础。这一解耦思路可以应用于：
- **推理时计算分配**：简单查询可以提前退出（early exit），复杂查询可以使用更深的计算。
- **缓存策略设计**：理解结果可以跨查询复用，预测特化需要每次重新计算。
- **模型蒸馏**：可以针对理解和预测分别设计蒸馏目标。

### 6.3 自蒸馏作为通用修复手段

CoMem 中自蒸馏 LoRA 修复深度截断保真度损失的策略具有通用性。在任何引入信息损失的结构化压缩（如层剪枝、宽度剪枝、注意力头剪枝）中，都可以使用自蒸馏来弥合压缩前后的表示差距。关键在于：
- 自蒸馏只需要未压缩模型的输出作为目标，不需要额外标注。
- 小型 LoRA 适配器即可有效修复，训练成本可控。

### 6.4 评估协议的严谨性

论文采用 chat-template-free 协议、对话聚类重采样和独立评判者等多重验证手段，体现了评估的严谨性。这提醒我们在研究中：
- 评估协议的选择会显著影响结论。
- 应使用多种互补的评估方法来验证核心结论的稳健性。
- 对于出人意料的结论（如 CoMem 远超全上下文），更需要严格的控制实验来排除偶然因素。

### 6.5 效率与性能的权衡设计

CoMem 在效率（18.26 GB vs 89.36 GB，7.83x 加速）和性能（RULER 97.05 vs 34.59）上同时取得优势，这打破了"效率提升必然牺牲性能"的传统认知。其关键在于正确识别了哪些计算是查询无关的（可以预计算和缓存）、哪些是查询条件化的（必须实时计算）。这种"计算分离"的思路可以广泛应用于系统设计。

### 6.6 对模型压缩研究的启示

CoMem 的层轴压缩与传统的 token 轴 KV cache 压缩形成了互补：
- Token 轴压缩减少每个层需要处理的 token 数量。
- 层轴压缩减少每个 token 需要计算的层数。
- 两者可以正交组合，形成多维度压缩策略。

对于模型压缩研究而言，CoMem 提供了一个新的视角：压缩不必局限于单一维度，而可以从模型的结构特性出发，找到新的压缩维度。

---

> **总结**: CoMem 通过发现 Transformer 深度方向上的分工现象，提出了一种沿层轴组织长上下文记忆的新范式。其核心创新在于将上下文的理解（浅中层）与预测特化（上层）解耦，实现读取计算量和内存独立于存储上下文长度。在 Qwen3-8B 上的实验显示，CoMem 在 RULER（97.05 vs 34.59）和 LoCoMo（38.27 vs 34.59）上均大幅超越全上下文 KV-Direct，同时在 128k 上下文下实现 7.83x prefill 加速和 79.6% 的显存节省。这一工作为长上下文处理开辟了层轴优化的新方向，对模型压缩和高效推理研究具有重要启发意义。
