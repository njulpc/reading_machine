# 深度技术分析：LAST: The Last Query Token Guides Visual Token Pruning for Edge-Cloud Collaborative MLLM Inference

## 1. 核心速览

- **研究话题**：边缘-云协同多模态大语言模型（MLLM）推理中的查询相关视觉 token 剪枝，即在视觉 token 传输至云端模型前，在边缘侧根据查询内容选择最相关的视觉 token 子集。
- **一句话总结**：LAST 利用因果注意力下最后一个查询 token 对视觉 token 的注意力作为轻量查询感知重要性信号，在紧凑边缘 VLM 上仅需单次无解码 prefill 即可完成剪枝，保留 12.5% 视觉 token 时在 11 个多模态基准上保持 95.4% 全 token 精度。

## 2. 研究背景与动机

多模态基础模型正在重塑边缘-云视觉智能：边缘设备将视觉输入编码为 token 并传输给通用云端 MLLM，通过共享推理骨干支持多样化下游任务。然而，视觉编码器通常保留密集的 patch 级表示，许多 token 视觉冗余或与当前查询弱相关，处理完整视觉序列会显著增加云端计算和通信成本。

现有视觉 token 剪枝方法主要面向集中式推理，无法满足边缘-云协同需求：

- **视觉驱动方法**（如 VisionZip、VisPruner）使用视觉注意力、显著性或特征相似度，但查询无关（query-agnostic），可能丢弃视觉不显著但对回答关键的区域。
- **查询引导方法**（如 FastV、SparseVLM）利用目标 VLM 中的文本-视觉交互，但必须先处理完整视觉序列才能获得相关性信号，无法在传输前完成剪枝。
- **紧凑模型引导方法**（如 SGP）用小型 VLM 引导大模型剪枝，但需要聚合多个查询 token 的注意力或进行自回归生成，引入额外边缘计算开销。

核心挑战在于：**能否在边缘侧用轻量信号估计查询相关的视觉重要性，且该信号需捕获完整的图像-查询上下文？**

## 3. 核心方法与创新点

**（1）最后查询 token 注意力评分（Last-Query-Token Attention Scoring）**

LAST 的核心观察是：在因果注意力（causal attention）机制下，最后一个查询 token 可以关注完整的视觉前缀和全部前序查询上下文。因此，最后一个查询 token 对视觉 token 的注意力天然构成一个简洁的查询条件化相关性信号——无需聚合所有查询位置、无需生成初步答案、无需访问云端模型内部状态。

具体而言，边缘侧紧凑 VLM M_e 对完整多模态提示执行单次无解码 prefill（decoding-free prefill pass），从注意力矩阵中提取最后一个查询 token 对 N 个视觉 token 的注意力权重作为重要性分数。该操作仅需一次前向传播，无自回归生成开销。

**（2）边缘-云 token 接口（Edge-Cloud Token Interface）**

LAST 在 InternVL 模型族上实例化，利用其共享视觉编码器提供的兼容 token 接口：
- 共享视觉编码器 E 产生 N 个视觉 token X = E(I) = [x_1, ..., x_N] ∈ R^{N×d_v}，E 包括共享视觉骨干和空间 token 化操作。
- 边缘和云端模型使用完全相同的编码器参数和视觉 token 布局，但各自有独立的 token 级连接器（connector）。
- 选定的视觉 token 直接通过云端模型的原生连接器被消费，无需额外对齐或重训练。

这一设计使得边缘侧选定的 token 可无缝接入云端模型，实现了"边缘选择、云端推理"的完全解耦。

**（3）重要性加权 k-center 选择（Importance-Weighted k-Center Selection）**

在固定 token 预算下，LAST 不仅依据注意力重要性选择 token，还结合特征空间多样性避免冗余分配到邻近或语义相似区域。具体采用重要性加权的 k-center 选择策略：在最大化注意力重要性的同时确保选定 token 在特征空间中的覆盖度，避免多个 token 聚集于图像同一区域。

**（4）无训练框架**

LAST 完全无需训练，所有模型参数保持冻结。边缘 VLM 仅执行一次 prefill 前向传播提取注意力信号，不需要额外的训练数据、微调或学习模块。

## 4. 实验设计与结果

LAST 在 11 个多模态基准上、多种 token 预算下进行评估，对比不同引导策略的剪枝方法。

- **核心指标**：保留仅 12.5% 视觉 token 时，在 11 个基准上保持 95.4% 的全 token 精度。这意味着剪枝 87.5% 视觉 token 仅损失约 4.6% 精度。
- **基线对比**：LAST 在多种 token 预算下一致优于查询无关方法（VisionZip、VisPruner）、查询相关方法（FastV、SparseVLM）和紧凑模型引导方法（SGP）。
- **模型族泛化**：除 InternVL 外，在 LLaVA 模型族上的实验验证了边缘-云剪枝范式的跨架构泛化能力。
- **系统级开销**：系统级测量验证了 LAST 的边缘侧选择开销极低，单次 prefill 远低于自回归生成或多查询位置聚合的开销。
- **精度-计算权衡**：LAST 在精度-token 和精度-计算权衡上均取得优势，同时减少视觉序列长度和云端计算量。

## 5. 局限性与未来展望

**局限性**：（1）依赖边缘和云端模型共享同一视觉编码器和 token 布局，若边缘和云端使用不同视觉编码器（如边缘用 CLIP、云端用 SigLIP），则选定 token 无法直接接入云端模型；（2）最后一个查询 token 的注意力虽捕获了完整上下文，但仅反映单一位置的视角，可能对复杂多步推理查询的覆盖不充分；（3）边缘 VLM 的能力上限决定了重要性信号的质量，若边缘模型过小可能无法准确识别查询相关区域；（4）k-center 选择的计算复杂度为 O(N·K)，在大 N（高分辨率图像）下仍有优化空间。

**未来展望**：（1）研究跨编码器 token 接口，使边缘和云端可使用不同视觉编码器；（2）探索多 token 注意力聚合的轻量化方案，在保持低成本的同时提升信号丰富度；（3）将 LAST 与自适应 token 预算结合，根据查询难度动态调整保留 token 数量；（4）扩展到视频流场景，处理时序维度的 token 剪枝；（5）与边缘-云端计算分配策略（如 SLM-LLM 协同）结合，形成完整的协同推理系统。

## 6. 学术启发 (Takeaways for My Research)

1. **因果注意力的"最后 token 全局视野"特性是一个被低估的信号源**。在因果注意力下，序列中最后一个 token 的注意力天然覆盖了所有前序 token，相当于一个"全局摘要"。这一特性不仅可用于视觉 token 剪枝，还可推广到上下文压缩（用最后 token 的注意力选择关键上下文）、检索增强生成（用最后查询 token 的注意力筛选检索文档）等场景。

2. **"预传输选择"问题定义精准抓住了边缘-云协同的独特约束**。传统剪枝方法假设选择和推理在同一设备完成，而边缘-云场景要求在云端模型看到完整序列前完成选择。这一约束催生了"不依赖目标模型内部状态"的需求，紧凑引导模型成为自然选择。这一问题定义对边缘 AI 系统设计具有范式参考价值。

3. **重要性+多样性的联合选择策略是 token 剪枝的标准范式**。LAST 和 CaRe 都采用了类似思路：先计算重要性分数，再用多样性约束避免聚集。k-center 选择确保空间覆盖度，注意力重要性确保查询相关性——两者的乘积式结合（重要性 × 边际多样性）平衡了"选最相关的"和"选最互补的"两个目标。

4. **共享编码器实现零成本跨模型 token 传输值得借鉴**。LAST 利用 InternVL 不同规模模型共享同一视觉编码器的设计，使得边缘小模型选定的 token 可直接被云端大模型消费。这一"编码器共享、连接器分离"的架构设计为多模型协同提供了简洁接口，在模型蒸馏、知识迁移等场景也有应用潜力。
