## 一、核心速览

### 研究主题

本文研究**大语言模型（LLMs）的 token 级动态宽度剪枝（token-level dynamic width pruning）**问题。具体而言，针对现有静态结构化剪枝方法因输入无关的计算分配导致激进修剪下精度严重退化，以及现有动态稀疏方法粒度粗、实际加速困难的问题，提出了首个端到端可微的 token 级动态宽度剪枝框架 WIDE，将动态剪枝从层级决策扩展到神经元块级粒度，并同时覆盖 prefill 和 decode 两个推理阶段。

### 一句话总结

WIDE 通过允许每个 token 动态选择注意力头组和 FFN 通道组实现神经元块级粒度的细粒度计算分配，配合两阶段训练管线学习有效的 token 级稀疏执行模式，并提出剪枝-内核协同设计框架将动态稀疏加速分解为掩码重排序、硬件无关块级跳过和硬件相关块内跳过三层，在 50% 稀疏度下较 SOTA 动态深度剪枝提升 55.1% 性能，实现 prefill 1.98 倍、decode 4.95 倍的内核级加速，以及 1.68 倍和 1.55 倍的端到端加速。

## 二、研究背景与动机

### 现有研究的痛点

1. **静态结构化剪枝的输入无关性**：静态结构化剪枝方法在部署前固定地移除特定的注意力头或 FFN 通道，对所有输入使用相同的计算结构。这种方式硬件友好，能够提供实际的吞吐量提升。然而，其根本缺陷在于输入无关性（input-agnostic）——不同的输入对模型不同部分的需求是不同的，某些输入可能需要被静态剪掉的头/通道来正确处理。当稀疏度较高（aggressive sparsity）时，这种固定剪枝策略会导致显著的精度退化，因为被永久移除的计算单元可能在处理特定输入时是关键的。

2. **动态稀疏方法的粗粒度局限**：为了解决静态剪枝的输入无关性问题，动态稀疏方法应运而生，通过根据个体输入自适应地分配计算量来提升质量保持。然而，现有动态稀疏方法主要局限于粗粒度的结构决策（如层级跳过/深度剪枝），即以整层为单位决定是否执行计算。这种粗粒度决策的问题在于：同一层内的不同注意力头和 FFN 通道对不同输入的贡献可能差异巨大，以层为单位的二值决策无法捕捉这种内部异质性，导致在保留质量方面仍有较大改进空间。

3. **动态稀疏的实际加速困难**：动态稀疏方法的另一个严峻挑战是实际加速。虽然理论上减少了计算量，但由于计算结构在推理时动态变化，难以高效映射到硬件上。现有的动态稀疏加速方案往往无法在真实的推理场景中实现与理论加速比匹配的实际加速，因为动态分支、不规则内存访问和内核调度开销会侵蚀大部分理论收益。这使得动态稀疏方法在学术上有吸引力但在实际部署中难以落地。

### 为什么要做这项研究

LLM 推理的计算成本是制约其大规模部署的核心瓶颈。prefill 阶段（处理输入提示）和 decode 阶段（逐 token 生成）都有各自的计算特征和效率挑战。理想的剪枝方法应当：①能够根据每个 token 的特征自适应地分配计算资源（输入感知）；②具备足够细的粒度以捕捉模型内部的异质性（神经元块级）；③能够在真实推理场景中实现与理论加速比匹配的实际加速（可落地）。WIDE 正是面向这三个目标设计的——通过 token 级动态宽度剪枝将动态决策从层级扩展到神经元块级，通过两阶段训练学习有效的稀疏模式，通过剪枝-内核协同设计实现实际加速。

## 三、核心方法与创新点

### 方法概述

WIDE 框架由两大核心部分组成：**token 级动态宽度剪枝机制**和**剪枝-内核协同设计框架**。前者解决"如何实现细粒度的动态计算分配"，后者解决"如何将动态稀疏高效地映射到硬件"。

### 核心创新

#### 创新一：Token 级动态宽度剪枝（Token-level Dynamic Width Pruning）

**问题**：如何将动态剪枝的粒度从层级扩展到神经元块级，同时保持可微性以支持端到端训练？

**方法**：
- WIDE 允许**每个 token 动态选择注意力头组（attention-head groups）和 FFN 通道组（FFN-channel groups）**，将动态剪枝从层级决策扩展到**神经元块级粒度（neuron-block-level granularity）**。
- 与层级深度剪枝（决定整层是否执行）不同，WIDE 在层内进行更细粒度的决策——每个 token 可以独立决定激活哪些注意力头组和哪些 FFN 通道组，同一层的不同 token 可以拥有不同的计算结构。
- 这种设计使得计算分配真正做到了 token 级和神经元块级的双重自适应：不同 token 根据其语义特征获得不同的"计算宽度"，关键 token 获得更宽的计算路径，冗余 token 获得更窄的计算路径。

**设计要点**：
- **可微分性**：WIDE 是首个端到端可微的 token 级动态宽度剪枝框架。可微分性使得剪枝决策可以通过梯度下降端到端优化，无需依赖启发式规则或强化学习，大大简化了训练流程并提升了优化质量。
- **双重覆盖**：WIDE 同时覆盖 prefill 和 decode 两个推理阶段，而非仅针对其中一个。prefill 和 decode 具有不同的计算特征（prefill 是计算密集型，decode 是内存密集型），WIDE 能够在两个阶段都实现有效的动态剪枝。
- **组级粒度**：以注意力头组和 FFN 通道组为单位（而非单个头/通道）进行剪枝决策，在细粒度和硬件效率之间取得平衡。组级粒度既比层级更细，又比单神经元级更易于硬件加速。

#### 创新二：两阶段训练管线（Two-Stage Training Pipeline）

**问题**：如何有效地学习 token 级稀疏执行模式，使其在保持质量的同时实现高稀疏度？

**方法**：
- WIDE 采用两阶段训练管线来学习有效的 token 级稀疏执行模式。
- 第一阶段（推测为校准/预热阶段）：在相对宽松的约束下学习基本的稀疏模式，让模型逐步适应动态计算分配。
- 第二阶段（推测为强化/微调阶段）：在目标稀疏度约束下进一步优化稀疏决策和模型参数，使稀疏模式更加精准。
- 通过两阶段的渐进式训练，WIDE 能够学到比现有方法更有效的稀疏执行模式，在相同稀疏度下保持更好的质量。

**设计要点**：
- **渐进式学习**：两阶段设计避免了直接在高稀疏度约束下训练可能导致的训练不稳定和质量崩塌，通过渐进式约束收紧使模型逐步适应稀疏执行。
- **质量保持优势**：两阶段训练使 WIDE 在质量保持方面显著优于现有方法——在 50% 稀疏度、仅校准设置下，性能较 SOTA 动态深度剪枝提升 55.1%。

#### 创新三：剪枝-内核协同设计框架（Pruning-Kernel Co-Design Framework）

**问题**：如何将细粒度的动态稀疏高效地映射到硬件，实现与理论加速比匹配的实际加速？

**方法**：
- WIDE 提出了一个剪枝-内核协同设计框架，将动态稀疏加速分解为三个层次：
  1. **掩码重排序（Mask Reordering）**：对动态生成的稀疏掩码进行重排序，使得需要执行的块在内存中连续排列，减少不规则内存访问。
  2. **硬件无关块级跳过（Hardware-Agnostic Block-Level Skipping）**：在块级别跳过被剪枝的计算单元，这一操作不依赖特定硬件特性，可在不同平台上通用。
  3. **硬件相关块内跳过（Hardware-Dependent Intra-Block Skipping）**：在块内部利用特定硬件的特性（如 SIMD 指令、张量核心等）进一步跳过被剪枝的计算，实现更细粒度的加速。

**设计要点**：
- **分层加速**：三层分解使动态稀疏加速从"all-or-nothing"变为渐进式优化——即使某些层次的加速无法实现，其他层次仍可提供加速收益，提升了框架的跨平台适应性。
- **硬件无关与硬件相关分离**：将通用的块级跳过与平台特定的块内跳过分离，使框架既能快速迁移到新平台（通过硬件无关层），又能在特定平台上榨取最大性能（通过硬件相关层）。
- **协同设计哲学**：框架名称"剪枝-内核协同设计"强调了剪枝策略与内核实现的联合优化——剪枝决策考虑内核执行效率，内核设计适配剪枝生成的稀疏模式，而非将两者割裂。

## 四、实验设计与结果

### 实验设置

- **推理场景**：覆盖 prefill（输入处理）和 decode（输出生成）两个推理阶段，分别评估加速效果。
- **稀疏度设置**：主要在 50% 稀疏度下评估，代表较为激进的剪枝比例。
- **对比方法**：与 state-of-the-art 的动态深度剪枝方法对比，包括仅校准（calibration-only）设置和训练设置。
- **加速评估**：同时报告内核级加速（理论加速比的上界）和端到端加速（实际部署中的加速效果）。
- **评估维度**：质量保持（性能提升百分比）和效率提升（加速比）。

### 主要结果

#### 1. 质量保持（50% 稀疏度，仅校准设置）

在 50% 稀疏度、仅校准设置下，WIDE 较 SOTA 动态深度剪枝方法提供了 **55.1% 的性能提升**。这一结果表明：

- token 级、神经元块级的细粒度动态剪枝在质量保持方面显著优于层级动态深度剪枝。
- 两阶段训练管线有效地学习了高质量的稀疏执行模式，使模型在高稀疏度下仍能保持优异性能。
- 55.1% 的性能提升是一个相当大的幅度，说明从层级到神经元块级的粒度细化带来了质变而非量变——层级剪枝无法捕捉的层内异质性在 WIDE 中被充分利用。

#### 2. 内核级加速

在 prefill 和 decode 推理工作负载下，WIDE 实现了接近理论上限的内核级加速：

| 推理阶段 | 内核级加速比 |
|----------|:-----------:|
| Prefill  | 最高 1.98x  |
| Decode   | 最高 4.95x  |

关键发现：
- **Decode 阶段的加速比（4.95x）远高于 prefill 阶段（1.98x）**，这与两个阶段的计算特征一致——decode 是内存密集型，动态宽度剪枝通过减少激活的神经元数量直接减少了内存访问量，而内存访问往往是 decode 阶段的主要瓶颈。
- 加速比"接近理论上限"表明剪枝-内核协同设计框架有效地将动态稀疏映射到了硬件上，最小化了动态分支和内存访问的开销。

#### 3. 端到端加速

| 推理阶段 | 端到端加速比 |
|----------|:-----------:|
| Prefill  | 1.68x       |
| Decode   | 1.55x       |

关键发现：
- 端到端加速比低于内核级加速比，这是因为端到端推理包含除目标内核外的其他开销（如注意力计算、embedding 查找、采样等），这些非剪枝部分的速度不变，稀释了整体加速效果。
- Prefill 的端到端加速（1.68x）略高于 decode（1.55x），尽管 decode 的内核级加速更高。这可能是因为 prefill 阶段 FFN 计算占总计算的比例更高，而 WIDE 主要剪枝 FFN 通道组，因此在 prefill 阶段的端到端收益更显著。
- 1.55x-1.68x 的端到端加速在实际部署中是有意义的提升，表明 WIDE 不仅在理论上有效，在真实推理场景中也能带来实质性的加速。

#### 4. 综合评价

WIDE 在质量和效率两个维度上都取得了显著突破：55.1% 的质量提升证明了细粒度动态剪枝的有效性，1.55x-1.68x 的端到端加速证明了剪枝-内核协同设计的实用性。这两个结果共同确立了 WIDE 作为首个端到端可微 token 级动态宽度剪枝框架的地位，证明了细粒度动态稀疏在质量和效率上可以同时超越粗粒度方法。

## 五、局限性与未来展望

### 局限性

1. **端到端加速与内核级加速的差距**：尽管内核级加速比高达 1.98x-4.95x，但端到端加速比仅为 1.55x-1.68x。这一差距表明非剪枝部分（如注意力计算、embedding、采样等）构成了显著的加速瓶颈。对于注意力密集型任务（如长上下文推理），FFN 剪枝带来的端到端收益可能进一步被稀释。

2. **仅验证于 50% 稀疏度**：论文主要报告了 50% 稀疏度下的结果，更高稀疏度（如 70%、80%）下的质量和加速效果尚未明确。在更激进稀疏度下，token 级剪枝的决策可能变得更加困难，质量保持的挑战也更大。

3. **训练开销**：两阶段训练管线虽然提升了质量保持，但也增加了训练成本。与免训练的静态剪枝方法相比，WIDE 的部署门槛更高，需要额外的训练资源和数据。

4. **硬件依赖性**：虽然框架设计了硬件无关层和硬件相关层，但最优加速效果依赖于硬件相关的块内跳过实现。不同硬件平台（如 NVIDIA GPU vs AMD GPU vs Apple Silicon）需要分别优化块内跳过内核，增加了工程成本。

5. **组级粒度的权衡**：以注意力头组和 FFN 通道组为剪枝单位，虽然比层级更细，但仍比单个头/通道粗。在某些场景下，组内不同头/通道的重要性可能差异较大，组级剪枝可能导致"要么全留、要么全剪"的次优决策。

6. **动态决策开销**：每个 token 需要动态生成稀疏掩码，这引入了额外的计算开销（如路由网络的推理）。虽然论文报告了净加速，但动态决策本身的计算成本在大规模部署中不容忽视。

### 未来展望

1. **注意力剪枝扩展**：将动态宽度剪枝从 FFN 通道组扩展到注意力计算的更多维度（如序列维度、头维度），进一步提升端到端加速比。

2. **自适应稀疏度**：探索输入自适应的全局稀疏度调节——简单输入使用更高稀疏度，复杂输入使用更低稀疏度，在质量和效率之间实现更灵活的动态权衡。

3. **更高稀疏度探索**：系统评估 70%-90% 稀疏度下的表现，探索 token 级动态宽度剪枝的极限，并研究在极端稀疏下保持质量的策略。

4. **跨平台内核优化**：为更多硬件平台（AMD GPU、Apple Silicon、ARM CPU）开发优化的块内跳过内核，降低跨平台部署的工程成本。

5. **与 KV-Cache 管理结合**：将 token 级动态宽度剪枝与 KV-Cache 剪枝/压缩结合，同时在宽度维度和序列维度实现动态计算分配，追求更大幅度的端到端加速。

6. **免训练变体**：探索基于校准数据的免训练 token 级动态宽度剪枝方法，降低部署门槛，使 WIDE 的核心思想能够以更低的成本应用到更多场景。

## 六、学术启发

1. **粒度细化是动态稀疏的关键方向**：WIDE 的核心贡献在于将动态剪枝的粒度从层级扩展到神经元块级，并证明了这一细化带来了 55.1% 的质量提升。这一结果有力地论证了：在动态稀疏中，粒度越细，对模型内部异质性的捕捉越精确，质量保持越好。这启发未来研究应继续探索更细粒度的动态稀疏（如单个神经元级、甚至权重级），同时关注细粒度与硬件效率之间的平衡。

2. **剪枝-内核协同设计的必要性**：WIDE 的剪枝-内核协同设计框架是一个重要方法论贡献。它指出：动态稀疏的实际加速不能仅靠剪枝算法，必须与内核实现联合设计。三层分解（掩码重排序、硬件无关块级跳过、硬件相关块内跳过）为未来的动态稀疏加速研究提供了清晰的架构模板。这一思路可推广到其他动态计算场景（如动态注意力、动态路由）的加速实现。

3. **可微分性降低部署门槛**：WIDE 是首个端到端可微的 token 级动态宽度剪枝框架。可微分性的重要性在于：它将剪枝决策的优化从启发式/强化学习转变为标准梯度下降，大大简化了训练流程。这启示我们：在设计动态计算分配方法时，应优先追求可微分性，使得整个系统能够通过统一的优化框架端到端训练。

4. **Prefill 与 Decode 的差异化加速**：WIDE 在 prefill 和 decode 两个阶段实现了不同的加速特征（prefill 内核 1.98x、decode 内核 4.95x），这反映了两个阶段的计算瓶颈不同。这一发现启示我们：LLM 推理加速应针对 prefill 和 decode 分别优化，而非采用统一的加速策略。特别是 decode 阶段的内存瓶颈使得宽度剪枝在此阶段的价值更为突出。

5. **端到端加速的稀释效应**：内核级加速（1.98x-4.95x）与端到端加速（1.55x-1.68x）之间的差距揭示了"局部优化"与"全局收益"之间的稀释效应。这提醒研究者：在报告加速效果时，应同时提供内核级和端到端指标，避免仅报告内核级加速而给读者过高期望。同时，未来的工作应关注如何减少非剪枝部分的瓶颈，缩小内核级与端到端之间的差距。

6. **对 LLM 推理优化的系统性启示**：WIDE 将动态剪枝从"学术概念"推向了"可落地方案"。其系统性贡献在于：证明了细粒度动态稀疏不仅可以显著提升质量保持，还可以通过精心设计的内核协同实现接近理论的加速。这为 LLM 推理优化指明了一条可行路径——在宽度维度实现 token 级动态计算分配，而非仅依赖深度剪枝或静态结构化剪枝。未来的 LLM 效率研究可以在此基础上进一步探索宽度、深度、序列三维度联合的动态计算分配。
