# 深度技术分析：Fidelity Is Not Safety: Gently-Compressed LLMs Pass Every Data-Free Quality Guard Yet Invent Procedure Steps in Agentic Execution

## 1. 核心速览

**研究话题**：温和压缩后的 LLM 虽通过所有数据无关的质量检查，但在智能体执行中会发明不存在的程序步骤。

**一句话总结**：跨越三种模型家族发现，温和压缩模型（低秩 SVD 截断）能全数通过困惑度、MMLU 和数据无关的输出保真度检查，但在执行标准操作程序（SOP）时会发明指令中从未存在的步骤；而同等困惑度的幅度剪枝则无此现象——根源在于压缩误差的"相干性×速率"乘积而非误差幅度，作者据此提出了一种跨架构通用的双轴数据无关筛选统计量。

## 2. 研究背景与动机

### 2.1 压缩模型的质量评估栈
当前从业者通过三层检查来接受压缩模型：困惑度在原始模型小因子范围内、下游准确率（如 MMLU）在置信区间内、数据无关的输出保真度信号（比较压缩与原始网络在随机探测输入下的内部表征）。这套检查栈存在一个盲点。

### 2.2 智能体执行的特殊风险
当压缩模型作为智能体执行标准操作程序（SOP）时，即使通过了所有质量检查，仍可能产生危险的"发明步骤"行为——这种幻觉在常规基准中不会被检测到。

## 3. 核心方法与创新点

### 3.1 方法概述
本文系统性地审计了压缩模型的质量评估栈，发现：
1. 在三种模型家族上，低秩 SVD 截断的温和压缩模型通过了所有标准质量检查
2. 这些模型在 SOP 执行中发明了不存在的程序步骤
3. 同等困惑度下的幅度剪枝不出现此现象
4. 通过配对置信区间隔离了原因：压缩误差的"相干性×速率"乘积是关键——误差幅度本身不能预测损害

### 3.2 分点创新
- **操作符特异性发现**：低秩 SVD 截断诱发发明步骤，而幅度剪枝（匹配到相同困惑度）不诱发——这表明问题不在压缩强度，而在压缩方式
- **配对输出保真度测试的 dissociation**：通过同一组压缩权重上的配对测试发现，CI 赢得输出保真度测试的同时 CI 失败发明步骤 canary 测试
- **双轴数据无关筛选统计量**：提出"相干分数（coherent-fraction）"和"误差速率（error-rate）"两个轴的统计量，用固定阈值即可跨架构标记失败构建，且与"相干性×速率"机制匹配
- **预注册、有功效的 canary 实验**：在三种架构上通过配对置信区间系统表征了盲点和 dissociation

## 4. 实验设计与结果

### 4.1 实验设置
- 三种模型家族（具体名称摘要未提供）
- 两种压缩算子：低秩 SVD 截断、幅度剪枝
- 控制困惑度匹配
- 三层质量检查：困惑度、MMLU、输出保真度
- 智能体 SOP 执行测试
- 预注册、有功效的 canary 实验设计

### 4.2 核心实验结果
- 温和压缩模型（低秩 SVD）**全数通过**困惑度、MMLU 和数据无关保真度检查
- 低秩 SVD 模型在 SOP 执行中**发明不存在的程序步骤**
- 幅度剪枝（匹配相同困惑度）**不出现**此现象
- 配对保真度测试与 canary 测试存在 **dissociation**
- 双轴统计量（相干分数 × 误差速率）能**跨架构固定阈值**标记失败构建
- 困惑度保护失效出现在模型具有"in-guard 低秩余量"的位置

### 4.3 结果讨论
核心发现颠覆了"通过质量检查 = 安全部署"的直觉。低秩压缩产生的误差具有空间相干性（即误差集中在某些方向），这种相干性在表征空间中形成系统性的偏差模式，在需要精确遵循指令的智能体执行中被放大。而幅度剪枝的误差更随机分散，不会产生同样的系统性偏差。双轴统计量为部署前筛选压缩模型提供了实用工具。

## 5. 局限性与未来展望

### 5.1 局限性
- 仅测试了两种压缩算子（低秩 SVD、幅度剪枝），其他压缩方式（量化、知识蒸馏、结构化剪枝）的行为未知
- 智能体任务局限于标准操作程序执行，其他智能体场景（如工具调用、多轮对话）中的行为未测试
- 双轴筛选统计量的阈值固定依赖于实验校准，极端规模模型上的适用性未验证
- 摘要未提供具体的"发明步骤"发生率数字

### 5.2 未来展望
- 扩展压缩算子覆盖：验证量化、蒸馏等方式是否存在类似的算子特异性风险
- 开发压缩感知的安全训练方法：在压缩目标中显式加入智能体执行安全约束
- 将双轴统计量集成到模型压缩工具链中，作为默认的安全筛选步骤
- 探索"相干性-aware"压缩：在压缩过程中主动打散相干误差

## 6. 学术启发

### 6.1 可迁移思路
- **质量检查栈的盲区审计**：任何评估体系都可能有盲区，通过设计针对性的"canary 测试"来发现盲区是通用的安全研究方法
- **算子特异性风险评估**：同样的压缩强度，不同的压缩方式可能产生完全不同的安全风险——压缩研究应从"压缩率-精度"二维扩展到"压缩率-精度-安全"三维

### 6.2 实验设计借鉴
- 配对置信区间（paired CI）在同一组模型上的双重测试是隔离因果机制的有力工具
- 困惑度匹配设计（匹配困惑度后对比不同算子）是控制混淆变量的精妙方法
- 预注册 + 有功效分析提升了实验结论的可信度

## 7. 总结

本文揭示了一个令人警醒的事实：通过所有标准质量检查的温和压缩模型仍可能在智能体执行中表现出危险的幻觉行为，且这种风险是压缩算子特异性的（低秩 SVD 诱发，幅度剪枝不诱发）。关键机制是压缩误差的"相干性×速率"乘积而非误差幅度。作者提出的双轴数据无关筛选统计量为部署前安全筛查提供了实用工具。这项工作对 LLM 压缩的安全评估具有范式性意义——困惑度、MMLU 和保真度不能证明智能体安全。
