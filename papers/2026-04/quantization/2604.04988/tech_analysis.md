# 深度技术分析：Prune-Quantize-Distill: An Ordered Pipeline for Efficient Neural Network Compression

## 1. 核心速览

**研究主题**：以实测延迟为目标的有序压缩流水线（剪枝→INT8 QAT→蒸馏）实证研究。

**一句话总结**：在 CIFAR-10/100 + ResNet-18/WRN-28-10/VGG-16-BN 上系统比较发现：INT8 QAT 贡献主要运行时收益，剪枝主要作为容量预处理器提升后续低比特优化鲁棒性，KD 殿后恢复精度；有序流水线达 0.99–1.42ms CPU 延迟，顺序消融证实阶段次序显著影响效果。

## 2. 研究背景与动机

参数量/FLOPs 等压缩代理指标不可靠预测墙钟时间——非结构化稀疏甚至会让 CPU 推理稍慢（不规则访存 + 稀疏 kernel 开销）。压缩研究需要在“精度-体积-实测延迟”联合空间中重新评估。

## 3. 核心方法与创新点

- **有序流水线**：非结构化剪枝 → INT8 QAT → KD 的固定次序组合。
- **角色分工发现**：QAT = 延迟收益主力；剪枝 = 容量预处理器；KD = 精度恢复器且不改变部署形态。
- **顺序消融**：固定 20/40/40 epoch 配额下，所提顺序在测试排列中普遍最优。

## 4. 实验设计与结果

三种骨干 × 两数据集：有序流水线精度-体积-延迟前沿优于任何单一技术；CPU 延迟 0.99–1.42ms，精度有竞争力。

## 5. 局限性与未来展望

局限：限于 CNN 与小数据集，LLM/Transformer 上结论可能不同；非结构化稀疏的硬件收益依赖稀疏 kernel；epoch 配额固定，资源分配敏感性未探索。未来方向：Transformer/LLM 验证、结构化剪枝版本、顺序自动搜索。

## 6. 学术启发

- 压缩方法组合时“顺序即方法”，应像消融模块一样消融顺序。
- 实测延迟应取代 FLOPs 成为压缩论文的默认主指标。
