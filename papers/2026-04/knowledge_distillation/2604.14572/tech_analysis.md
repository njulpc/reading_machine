# 深度技术分析：Don't Retrieve, Navigate: Distilling Enterprise Knowledge into Navigable Agent Skills for QA and RAG

## 1. 核心速览

**研究主题**：将文档语料离线蒸馏为层级化技能目录，供 LLM 智能体导航式问答。

**一句话总结**：Corpus2Skill 把企业语料库离线蒸馏成层级技能目录，服务时让 LLM 智能体从鸟瞰视图逐层下钻到文档、走不通就回溯，在企业客服基准上答案质量与溯源性均优于单次稠密/混合/层级检索及 agentic RAG 基线；十子集泛化研究同时界定了其适用边界。

## 2. 研究背景与动机

RAG 把模型当作检索结果的被动消费者，模型看不到语料的整体组织结构，也不知道还有什么没看过。对结构良好的企业知识库，这种"只见树木不见森林"的检索范式浪费了语料内在的主题层级。

## 3. 核心方法与创新点

- **语料→技能目录的离线蒸馏**：将文档集合压缩为层级化的摘要目录（鸟瞰→分支→文档），本质是把语料知识蒸馏进一个可导航结构。
- **智能体导航替代检索**：服务时 LLM 主动下钻、评估分支价值、无果则回溯，把"一次性相似度匹配"变成"多步结构化探索"。
- **适用边界的系统刻画**：十子集泛化研究明确：对单一领域、主题分类可恢复的语料稳定受益；对开放域事实库或同质化表格语料（顶层聚类失效），扁平检索仍是更优选择。

## 4. 实验设计与结果

在企业客户支持基准上，答案质量与 grounding 双指标超越 dense、hybrid、hierarchical-retrieval 与 agentic RAG 四类基线，成本代价适中；泛化研究给出上述清晰的适用范围划分。代码开源。

## 5. 局限性与未来展望

局限：离线蒸馏目录需随语料更新而重建，增量维护成本未讨论；多步导航的时延高于单次检索；对语料结构质量依赖强。未来方向：目录的增量更新、导航与扁平检索的混合路由、向代码库/法规库等强结构语料推广。

## 6. 学术启发

- "蒸馏"的对象可以是整个语料库的组织结构，而非单模型权重——知识压缩的形态不止参数一种。
- 该文的"适用范围声明"是方法类论文的范本：主动给出失效条件（开放域、同质表格）反而增强方法可信度，值得压缩类论文效仿（如量化方法声明哪些层不可压）。
