## 1. 核心速览

研究主题：other。

一句话总结：DropKV 用单 token 淘汰造成的输出扰动构造可融合评分，5% KV 预算下保留更好的长上下文能力。

## 2. 研究背景与动机

长上下文 KV 缓存随序列长度线性增长。只看 attention probability 会忽略 value 对最终输出的贡献；直接最小化一组删除位置引起的误差，又是组合优化问题。本文将可解释的局部扰动与真正可运行的 GPU 实现联系起来。

## 3. 核心方法与创新点

1. 对注意力输出 a、权重 p_j、value v_j，单位置删除扰动为 p_j/(1-p_j)·(a-v_j)，删除评分最小的位置。联合集合的分母为 1-Σp_j，不能把单点分数当作严格可加的真实误差。
2. 在 w 个观察 query 上累加 [p_j/(1-p_j)]²‖a-v_j‖²。单 query 常数近似依赖小 attention 权重和残差锥对齐条件，不能解释为无条件最优。
3. FlashAttention 风格前向、评分和 split-K 合并共三个 Triton kernel；利用 ‖a-v‖²=‖a‖²+‖v‖²-2a·v 流式计算，避免 w×n×d 中间张量。

## 4. 实验设计与结果

官方表1：5% KV 预算，Llama-3.1-8B RULER 平均 82.00，full KV 84.84，AnDPro 79.65；Qwen2.5-7B-1M 为 83.77/87.01/79.90；Mistral-7B-512K 为 85.40/89.02/81.37。LongBench Llama 为 45.51，full KV 49.91，说明压缩有损。A100-80GB、w=8 时，评分 kernel 在 128K 达 19.8× 相对朴素 PyTorch 加速；端到端 matched-batch prefill 最多改善 9.9%，两者不可混用。5%预算可理解为目标缓存槽位约20倍缩减，不是整模20倍。

## 5. 局限性与未来展望

理论条件不自动适用于任意 query 或未来生成；观察窗口可能漏掉后续重要位置。5%预算仍有显著任务损失。kernel 对比的基线、上下文长度和 batch 会影响收益；本文未在本机复现 Triton/GPU 实验。

## 6. 学术启发

把压缩目标定义在模型输出空间，再推导能融合进 kernel 的代理，比仅调整 attention 分数更有研究价值。后续应测失效锥条件、未来 query 稳定性，以及压缩评分开销占端到端延迟的比例。
